# Story 2.4a: Ability runtime cast spine — cooldown SoA, cast command, and the AlgoVersion 6→7 fold

Status: done

<!-- Note: Validation is optional. Run validate-create-story for quality check before dev-story. -->

## Story

As a player,
I want abilities attached to a unit type to appear as activatable buttons on the in-game command card with cooldown, cost, and targeting feedback,
so that I can cast a unit's ability during a match and see it resolve through the deterministic effect engine.

## Acceptance Criteria

**AC1 — Command card shows an affordable/cooldown-aware ability button.** _(epic)_
**Given** a unit type whose `UnitDefinition` lists one active ability **When** an entity of that type is selected in Play mode **Then** the command card shows an ability button labeled with the ability (name + cost + cooldown state) **And** the button is **disabled when on cooldown or when Energy/ore/crystal is insufficient, matching the sim-side affordability check** (the same predicate the sim uses to accept/refuse the cast — no divergence between the greyed-out button and the sim's refusal).

**AC2 — Click → intent → sim cast (presentation never writes sim).** _(epic)_
**Given** an off-cooldown affordable ability with a `TargetUnit` targeting type **When** the player clicks it and selects a valid target **Then** an ability-cast **intent** is queued and consumed by the sim, the effect graph executes (via the 2.1 `EffectExecutor` + 2.2b `ModifierStore`), the cost is debited, and the cooldown begins **And** the presentation layer issued **only an intent** (a `UnitCommand.CastAbility` order through `LockstepManager.EnqueueOrder` / the shared `OrderApplier`) and **never wrote sim arrays directly**.

**AC3 — Deterministic + Fixed-time cooldown.** _(epic)_
**Given** the same cast performed in two identical replays **When** a golden checksum is taken after the cast resolves **Then** the checksums are **byte-identical** **And** the per-ability cooldown ticks down in Fixed time and the ability re-enables **exactly** when the cooldown reaches zero.

**AC4 — The scheduled determinism fold (AlgoVersion 6→7).** _(story-added)_
**Given** the new mutable-mid-match per-ability cooldown SoA **When** a checksum is computed **Then** the cooldown state is **folded into `SimChecksum.Compute`** (ascending entity-id, count-driven, `IsAlive`-guarded, `int`-only), `SimChecksum.AlgoVersion` is bumped **6→7** with a v7 doc line, the known-state guard (`SimChecksumCoverageGuardTest`) is re-pinned to the new v7 hash + `Assert.Equal(7, …)`, `VersionStampConsistencyTests.ExpectedSimChecksumAlgoVersion` is **7**, **all 8 existing goldens are re-recorded** in the same commit, and **one new cross-platform-safe `ability-cast` golden** (integer/Fixed-only, runs on BOTH CI legs) is added **And** `CanonicalModelHash.AlgoVersion` stays **2**, `ReplayRecorder.VERSION` stays **2**, `TickCommandPacket.PROTOCOL_VERSION` stays **1** (no start-state / wire / replay-format change).

**AC5 — Live==Replay parity, wire reused, no VERSION bump.** _(story-added)_
**Given** a `UnitCommand.CastAbility` order **When** it is applied live (`LockstepManager`), in replay (`ReplayPlayer`), and offline (`SelectionSystem`) **Then** all three route through the **single `OrderApplier.Apply` switch** and produce byte-identical post-state (extend `CommandApplyParityTests`) **And** the cast **reuses the unchanged 11-byte `UnitOrder` wire** (no new wire field, no `ReplayRecorder.VERSION` bump — the Story-1.12 precedent), with the ability slot + target packed into the existing `TargetX`/`TargetZ` raw-int fields.

**AC6 — A2 single-mapper + affordability refuse + scope fences.** _(story-added)_
**Given** the FIRST per-entity ability state (ability slots, cooldown slots, authored `MaxEnergy`) **When** any spawn path creates a unit **Then** those fields flow **only** through `EntityWorld.ApplyUnitDefinition` (the A2 single-mapper rule; `ApplyUnitDefinitionGuardTest` stays green) — never hand-copied in a spawn path — and a recycled slot never carries a prior occupant's ability/cooldown **And** when Energy/ore/crystal is insufficient **or** the slot is on cooldown the cast is **refused atomically** (nothing is debited, no cooldown starts, no effect runs) **And** the out-of-scope fences hold: `GroundPoint`-targeted casting, energy **regen**, and `CombatFeedbackProfile` (Story 2.7) are NOT built here; no `float` / `Dictionary`-enumeration / `using Godot;` enters sim code (analyzer clean).

_Covers: FR-11, AR-8, AR-9, NFR-4. Depends on: 2.3 (`AbilityDefinition` + `AbilityLoader` + `AbilityValidator` + `ContentJson.Options` — done), 2.2b (`ModifierStore.TryDebitEnergy` + the cast-time `EffectContext`/`ModifierStore` wiring — done), 2.2a (`Energy`/`MaxEnergy` SoA — done), 2.1 (`EffectExecutor` + `EffectContext` — done), 1.12 (`OrderApplier` single-switch + the wire-reuse precedent — done)._

### 🔑 Determinism posture — 2.4 DOES fold (AlgoVersion 6→7), the scheduled re-baseline

`AbilityCooldownTicks` is the first per-entity array that **becomes mutable mid-match** in this story → per [[chimera-checksum-fold-timing-rule]] it folds NOW (the rule is deterministic — apply + state it, do not re-ask). This is the same scheduled event as 1.12 (v4, command state), 1.13 (v5, separation), 2.2b (v6, modifiers). The other new arrays do **not** fold: `AbilityId`/`MaxEnergy` are authored/peer-identical (like `MeshType`/`BaseMaxHealth`); `PendingCast*` are transient-within-tick (set pre-tick by `OrderApplier`, consumed+cleared by `AbilityCastSystem` before the checksum). `AbilityCount` is folded only as the cross-platform-safe **count-driven loop bound** (mirrors `PatrolCount`). **Note the as-built precedent that `AttackCooldown` is NOT folded** — leave it as-is (out of scope; it is derived-redundant state and the coverage guard is a hand-list). Your new fold follows the explicit RULE, not the `AttackCooldown` gap.

### The wire decision (Decision #2) — reuse the 11-byte wire, support Self + TargetUnit, defer GroundPoint

`UnitOrder` is a frozen 11-byte struct: `unitId(2) + command(1) + targetX(4) + targetZ(4)` (`NetworkCommand.cs:72`). The two 4-byte target fields are **full** for a ground point — there is no room for an ability slot alongside a ground (x,z). But for **Self** and **TargetUnit** casts the slot + target id fit cleanly (slot in `TargetX`, target id in `TargetZ`), mirroring how 1.12 packed an entity id into `TargetX` for `AttackTarget`. **All three shipped sample abilities (`fireball`=TargetUnit, `minor_heal`=Self, `battle_fury`=Self) are Self/TargetUnit — none is GroundPoint** — and `EffectContext` has no ground-point field anyway. So 2.4 supports Self + TargetUnit on the **unchanged wire (no `ReplayRecorder.VERSION` bump — the 1.12 precedent)** and defers GroundPoint (which would force a wire widen 11→12 + a `VERSION` 2→3 bump + an `EffectContext` ground-point field + a UI ground reticle — a coherent later increment). The frozen `TargetX`=slot / `TargetZ`=targetId convention is read back as raw ints (`o.TargetX`/`o.TargetZ`) — **never `.ToFloat()`** (that corrupts the packed int; the 1.12 lesson, `NetworkCommand.cs:161-166`).

### Why the cast EXECUTES in a system, not in `OrderApplier.Apply`

`OrderApplier.Apply` is the single shared live/replay/offline switch — but **offline it runs at input time, OUTSIDE the tick** (`SelectionSystem` calls it synchronously; `LockstepManager`/`ReplayPlayer` call it during `Flush`, before `StepOnce`). Running an effect graph there would advance the shared `SimRng` and query a stale `SpatialHash` off-tick → desync vs the online/replay path. So `OrderApplier.Apply` only **writes the pending-cast intent** (2 SoA fields, like `AttackTarget` writes `CommandTarget`); the `AbilityCastSystem` (inside the tick, with full store access) **consumes + executes** it. This is the deterministic shape, and it co-locates cooldown tick-down with cast execution. Sequencing (`MainScene.cs:489-519`): `Flush` (sets intent) → `StepOnce` (systems run, `AbilityCastSystem@3` consumes intent) → checksum (intent already cleared).

### The cooldown timer — integer ticks (Decision #4)

`AbilityDefinition.Cooldown` is `Fixed` SECONDS. Store **remaining integer ticks** (`AbilityCooldownTicks`, decrement by 1/tick, gate on `> 0`, re-enable at exactly 0) — exact (no Fixed accumulation drift), folds as `int`, and is the doc-sanctioned conversion (`AbilityDefinition.cs:46`). Convert at cast: `(Cooldown * Fixed.FromInt(30)).ToInt()` (30 = sim ticks/sec; `Fixed.ToInt` is integer truncation — deterministic, **not** `ToFloat`). This is cleaner than the `AttackCooldown` seconds-decremented-by-`dt` approach (which drifts on the inexact Fixed `1/30`) — use integer ticks.
