## Intent

**Problem:** Story 7.8 shipped a read-only custom-UI widget tree (8 display kinds) and Story 7.5 shipped the deterministic custom-event system (registry + `allowed_raisers` field + checksum-folded `DslEventQueue`), but a creator still cannot make a widget *do* anything. There is no interactive `Button`, no path from a button press into the deterministic sim, and the `allowed_raisers` set that 7.5 authored is enforced only at load — never at runtime for an externally-injected raise. Without this, interactive custom games (vote buttons, buy-upgrade, ability-shop, spawn-wave) are impossible.

**Approach:** Add a `Button` widget kind that, when pressed, raises a *registered* custom event through the **lockstep command bus** — never mutating sim state directly. A new `UnitCommand.DslEvent` rides the existing 11-byte `UnitOrder` layout (event registry-index + up to two typed arg raws), is threaded through every command-application site (live, spectator, replay), is applied by the single `OrderApplier.Apply` into the checksum-folded `DslEventQueue`, and is **sim-side authorized** against the event's `allowed_raisers` set (deterministic drop for an unauthorized raiser — never a client-side button-disable). The replay format bumps to VERSION 3 and hard-rejects v1. A closed, presentation-only **local-action whitelist** (`ToggleWidgetVisible`/`OpenSubPanel`/`CloseSelf`/`SetLocalUiVar`) handles non-networked UI navigation entirely in the presentation layer, provably disjoint from sim/DSL namespaces and outside `SimChecksum`.

## Boundaries & Constraints

**Always:**
- **The write rail mutates sim ONLY through the lockstep command bus.** A button press calls `LockstepManager.EnqueueDslEvent(eventIndex, arg0, arg1)`; it never calls `DslEventQueue.Enqueue`, a sim system, or `ScenarioDirector` directly from presentation. The command is applied by the single `OrderApplier.Apply` at exec-tick, identically on every peer and in replay.
- **Sim-side raiser authorization, never client-side disable.** When `OrderApplier` applies a `DslEvent` order, a sim-side gate (`ScenarioDirector.TryEnqueueExternalDslEvent`) checks the sender faction ∈ the event's `AllowedRaisers` (with authored `-1` = system always legal). An unauthorized raise is a **deterministic no-op drop** — identical on all peers and in replay. The button is always pressable; authorization is a sim decision, not a UI decision. This closes the load-time-only enforcement gap 7.5 explicitly earmarked for 7.9.
- **Determinism is byte-identical.** Two headless runs of the same seeded scenario + identical button-command stream produce a byte-identical `SimChecksum`. The button raise enters the *existing* checksum-folded `DslEventQueue` (v18) at the deterministic command-application point (before `StepOnce`; the director drains it at its tick-start seed). No new sim state is added, so **`SimChecksum.AlgoVersion` stays 18** and the 24 world replay goldens stay byte-identical.
- **`Button` folds into the canonical model hash.** Add a `Button` case to the `CustomUiTree` typed fold (`MixWidget`): fold `Text`, `EventName`, each arg raw, the `LocalAction` kind (enum by name) and its target, in fixed field order — no JSON bytes; `_editor` excluded by construction. Bump `CanonicalModelHash.AlgoVersion` **10→11**, add the v11 docblock naming Story 7.9, and record exactly **one** named re-baseline (re-record `hero-start-state.golden.txt`, bump the AlgoVersion pins) in one commit. Divergent widget trees (one peer has the button, one doesn't) → different v11 hash → `HandshakeGate` blocks start. `StartStateHash.AlgoVersion` stays 2.
- **Strings never enter the tick.** The button stores an authored `EventName` string; it is resolved to the registry **index** (declaration order in `ScenarioData.CustomEvents`) presentation-side, once, at bridge init. The wire and `DslEventQueue` carry only the int index and int arg raws (Int/Bool = value, Fixed = `.Raw`).
- **Closed vocabulary, fail-closed parse (unchanged posture).** `Button` is added to the closed `WidgetKind` registry in `WidgetBaseJsonConverter`; unknown kinds still fail closed with a located error. The `LocalUiAction` enum is a closed set; unknown local actions reject at parse.
- **Wire budget = 2 args.** A `DslEvent` order reuses the fixed 11-byte `UnitOrder` (no wire widening → replay carries it for free). A button may therefore target only events declaring **≤ `EventBounds.MaxButtonEventParams` (2)** params; `CustomUiGate` rejects a button targeting a wider event with a located, constant-named error. (Wider-arg buttons are deferred, not silently truncated.)
- **Per-tick cap, drop-newest.** `LockstepManager.EnqueueDslEvent` enforces `EventBounds.MaxDslEventsPerTick` (drop-newest, never throw), mirroring the `_pendingCount < MAX_ORDERS` idiom; DslEvents also share the existing 32-order packet budget.
- **Replay bumps to v3, hard-rejects v1.** `ReplayRecorder.VERSION` 2→3. `ReplayPlayer` tightens its guard to reject `version < 2` (v1 is seed-incomplete and desync-prone); v2 (seed-complete, DslEvent-free) still plays; v3 round-trips `DslEvent` orders. The new order kind is threaded through `ReplayPlayer.ApplyOrders`.
- **Local actions are provably sim-free.** `ToggleWidgetVisible`/`OpenSubPanel`/`CloseSelf`/`SetLocalUiVar` are handled entirely inside `CustomUiBridge` (presentation), touching only Control visibility and a presentation-only local store. They never enqueue a command, never call sim/DSL code, and are proven (by test) to leave `SimChecksum` byte-identical.

**Block If:**
- The intended button vocabulary, the local-action whitelist set, or a cap value contradicts the epic's stated set/limits in a way that changes an observable acceptance outcome and the epic gives no basis to choose. (None expected — all are fixed by Epic 7 context line 50.)

**Never:**
- No sim mutation from presentation, no client-side button-disable/enable as an authorization mechanism, no bypass of `OrderApplier`.
- No `[JsonPolymorphic]`/reflection widget construction; no scripting escape hatch; no new packet type (DslEvents ride inside `TickCommands`).
- Do NOT bump `SimChecksum.AlgoVersion`, do NOT move any world replay golden, do NOT add new persistent sim state. Only `hero-start-state.golden.txt` moves (the CanonicalModelHash 10→11 re-baseline).
- Do NOT widen the `UnitOrder` wire layout or add a variable-length DslEvent record (would break the fixed-stride replay loop). Do NOT reorder/renumber existing `UnitCommand` values.
- No T3 editor (7.10), no win-condition presets (7.11), no new event *sources* or vocabulary (7.13).

## Design Notes

- **Why no `SimChecksum` bump (18 stays):** the button raise enters the *existing* 7.5 `DslEventQueue` — already folded at v18 — via `TryEnqueueExternalDslEvent`, at the deterministic command-application point (before `StepOnce`); the director drains it at its tick-start seed (`ScenarioDirector.cs:837-853`). No new persistent sim state is introduced, so the fold is unchanged. Only the *canonical model hash* moves, because a new widget kind enters the authored `CustomUi` tree it covers (10→11, one `hero-start-state` re-baseline — same shape as 7.8's 8→9).
- **Wire reuse over widening (the 2-arg budget):** `UnitOrder` is a fixed 11 bytes (`ushort UnitId + cmd + int TargetX + int TargetZ`) and the replay record loop is fixed-stride. Packing `eventIndex→UnitId`, `arg0→TargetX.Raw`, `arg1→TargetZ.Raw` carries a DslEvent through the wire AND replay for free with zero format risk. The cost is a ≤2-param ceiling for *button-raised* events (triggers can still raise wider events via 7.5's `RaiseEventNode`). This is the minimal shippable slice; a variable-length DslEvent record for 3–4 args is deferred, not truncated.
- **Runtime authorization is the load-time mirror, at a new seam:** 7.5 checks `allowed_raisers` only against authored `RaiseEventNode`s at load (`EventDispatchPlan.cs:254`). A button raise has no authored node to have been load-checked, so authorization MUST happen at runtime — and it must be sim-side (all peers + replay run `OrderApplier`), deterministic, and drop (not throw). `TryEnqueueExternalDslEvent` reuses the plan's precomputed per-event allowed-raiser array; `-1`/system is always legal (matches the field's documented contract, `ScenarioData.cs:476`).
- **v1 rejected, v2 kept (not "reject below v3"):** on disk `VERSION` is already 2 (SimRng seed; the epic's "bump to v2" text predates that). The intent says *v1* is hard-rejected — and v1 is genuinely unsafe (no captured seed → `DEFAULT_RNG_SEED` fallback → desync for any SimRng scenario). A seed-complete v2 replay is DslEvent-free and replays correctly (SimChecksum unchanged), so rejecting it would be gratuitous. Guard: reject `version < 2`; accept v2 and v3.
- **Local whitelist disjointness:** `LocalUiAction` is a closed enum consumed ONLY in `CustomUiBridge` (presentation). It never appears in the DSL node registry, never enqueues a command, and its "SetLocalUiVar" writes a presentation-only store (distinct from the sim `DslVarTable`). A test asserts `SimChecksum` is byte-identical whether local actions fire or not — the structural proof it is outside the checksum.
- **Example button JSON (canonical, `_editor` last):**
  `{"id":9,"kind":"Button","anchor":"BottomRight","x":-180,"y":-64,"w":160,"h":48,"text":"Buy Upgrade","event":"buy_upgrade","args":[1],"_editor":{...}}`
  A press by an allowed raiser enqueues `DslEvent(index_of("buy_upgrade"), 1, 0)`; the sim drains it and fires the subscribed trigger deterministically.
