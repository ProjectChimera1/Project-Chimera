## Story

As a creator,
I want an authorable unit-tag classification (Organic / Mechanical / Magical) that is separate from `damage_type` and `armor_type` and that the effect engine can filter and counter by,
So that I can build effects and counters like "bonus damage vs Mechanical" or "heal only Organic" without abusing the damage/armor matrix.

## Why this matters (source-verified)

Today a `UnitDefinition` carries three orthogonal combat facets — a `damage_type` string (`ParsedDamageType`, `UnitDefinition.cs:235-241`), an `armor_type` string (`ParsedArmorType`, `:244-251`), and a non-combat `category` archetype (`ParsedCategory`, `:267-275`) — **but no classification tag**. A repo grep for `UnitTag|ParsedTags|requireTag|TagsOf` returns only unrelated mod.io/manifest `"tags"` metadata (`ContentPackageManifest.cs`, `UGC/ModIoService.cs`), so the target names are free. The GDD lists the gap explicitly: the UnitDefinition resource should contain "damage type, armor type, ability list, **tag list (organic, mechanical, magical)**, combat feedback profile" (`Project_Chimera_GDD.md:168`) — the tag list is the only one not built.

DG-4 (`epics.md:245`) wants tags as an **effect-targeting & counter axis, distinct from damage/armor types**. Creators today can only express "counters Mechanical" by abusing the `damage_type × armor_type` `DamageMatrix` — but that matrix is a *different* axis (how much a hit is scaled), and overloading it entangles two independent design levers. This story adds the third axis so `SearchArea(require_tag: Mechanical)` and `heal only Organic` become first-class, closed, deterministic primitives on the AR-8 effect graph — **with no scripting escape hatch** (`2-1-*.md:91`: "the one and only effect surface … no scripting/eval escape hatch, ever").

This is a **textbook clone of Story 2.9a's `AttackDomainOf`**: a new authored-immutable `[Flags] byte` per-unit classification array, added via the same four `EntityWorld` sites + the single `ApplyUnitDefinition` mapper + a `Parsed*` accessor, read in-sim by the same `TargetMatcher`. 2.9a is the playbook; the two genuinely net-new surfaces are the **AC2 validator** (units are never validated today) and the **AC6 fold decision** (see Decisions).

_Covers: DG-4, AR-8. Depends on: 2.1 (`EffectNode` vocabulary + `SearchArea` + `EffectExecutor` — done), 2.3 (`AbilityDefinition` + `Validated<T>` + `AbilityValidator` located-error pattern — done). Sibling precedent (not a dep): 2.9a `AttackDomainOf`._

## Acceptance Criteria

### AC1 — `tags` deserializes to a distinct `UnitTag` axis + a per-entity SoA (epic AC1)

**Given** a `UnitDefinition` JSON declaring `tags: ["Organic","Magical"]` **When** it is loaded **Then** it deserializes into a new `string[]? Tags` field whose `ParsedTags` accessor resolves to a `[Flags] UnitTag` value **distinct from** `ParsedDamageType`/`ParsedArmorType`/`ParsedCategory` **And** a new per-entity `EntityWorld.TagsOf[]` SoA array is populated for each spawned entity via the single `ApplyUnitDefinition` mapper, leaving the existing `damage_type × armor_type` `DamageMatrix` path (`DamageTable.Get`) **byte-for-byte unchanged**.

- **AC1.1** `UnitTag` is a new `[System.Flags] enum UnitTag : byte { None=0, Organic=1<<0, Mechanical=1<<1, Magical=1<<2 }` in `godot/src/Core/UnitTag.cs` (namespace `ProjectChimera.Core`, sibling to `AttackDomain.cs`/`UnitCategory.cs`; pure C#, no Godot). **No `All` member** (unlike `AttackDomain` — an unauthored unit is `None`, not "all tags").
- **AC1.2** A unit MAY carry multiple tags (`["Organic","Magical"]` ⇒ `Organic|Magical`), OR-folded exactly like `ParsedAttackDomains` (`UnitDefinition.cs:282-300`).
- **AC1.3** The tag value is read from `TagsOf`, never from `armor_type`/`damage_type`/`category` — the four are independent axes (a `Magical` unit can be any armor/damage/archetype).

### AC2 — Closed-set validation with a located reject; no bad def spawns (epic AC2)

**Given** a `UnitDefinition` whose `tags` contains a token **not** in the closed set `{Organic, Mechanical, Magical}` (e.g. `"Undead"`) **When** the faction content is resolved before spawn **Then** it is **rejected fail-closed with a located error naming the unit id and the offending token** (e.g. `unit 'render_crawler'.tags: 'Undead' is not a known unit tag (Organic|Mechanical|Magical).`) **And** no rejected definition produces a spawnable entity.

- **AC2.1** The closed-set check runs in the faction-resolution pre-pass — the `ResolveAbilities` sibling site — on **both** legs: client `ScenarioLoadPhase.ResolveSlotFactionDefs` (`:106`) and server `ServerBootstrap.Build` (`:43-46`), so validation happens on every path before any `SpawnUnit`.
- **AC2.2** The located-error format mirrors `AbilityValidator.Located` (`AbilityValidator.cs:220-224`) and the closed set is enforced with a static `string[]` + `InSet` (the `ScenarioValidator.cs:298-309` idiom). The error names the unit id AND the offending token (asserted by a Tier-1 test, the `NegativeAbilityValidationTests.cs:39-47` shape).
- **AC2.3** Fail-closed = **drop the offending unit** (per-item, mirroring `AbilityRegistry` keeping only `Ok` abilities, `AbilityRegistry.cs:65,79`): a dropped unit makes `ScenarioApplier.GetUnit(u.UnitId)` return null → the existing `def == null → skip` sink (`ScenarioApplier.cs:117-121`) runs → no `Create()`/`SpawnUnit` → **no EntityWorld slot**. The rest of the faction still loads.
- **AC2.4** The `ParsedTags` runtime accessor stays lenient (unknown token contributes `None`, like `ParsedAttackDomains`) — it only ever runs on already-validated data. The **reject is the validator's job**, not the accessor's. (See D-2 for whether the validator mints a `Validated<T>` or is a lighter fail-closed drop.)

### AC3 — `SearchArea` tag predicate collects only tag-intersecting targets, ascending-id (epic AC3)

**Given** a 2.1 `SearchArea` node configured with a tag predicate `require_tag: Mechanical` **When** the effect executes over a mixed-tag candidate set **Then** only entities whose `TagsOf` **intersects** `Mechanical` are collected as targets (in ascending-id order), and every non-`Mechanical` candidate is skipped — asserted by exact target-id **count and membership**.

- **AC3.1** `require_tag` is a **new `UnitTag RequireTag` field on `SearchAreaEffect`** (default `None`), NOT a new `TargetFilter` bit — `TargetFilter : byte` is **already full** (all 8 bits used: `Self/Ally/Enemy/Neutral/Alive/Air/Ground/Structure`, `TargetFilter.cs:16-41`). Do **not** widen `TargetFilter` or pack tags into it (the story forbids overloading the existing axes).
- **AC3.2** The predicate is evaluated in `TargetMatcher.Matches` (`TargetMatcher.cs:29-46`) as an AND-constraint **beside** the 2.9a domain check: `if (requireTag != UnitTag.None && (world.TagsOf[candidateId] & requireTag) == UnitTag.None) return false;` — pure integer bit-AND (no `Fixed`/float/`Mathf`/RNG). **Intersection semantics** ("`TagsOf` intersects the required set", i.e. match if ANY required bit is set), matching the epic's "tag array intersects Mechanical".
- **AC3.3** `require_tag: None` (the default, and every pre-2.11 `SearchArea`) imposes **no constraint** — so every existing ability's `SearchArea` behaves **byte-identically** (the 2.9a "no domain bit = all domains" pattern). Ascending-id order is preserved for free: `SearchAreaEffect.FindTargets` already `Array.Sort`s candidates ascending (`:58`) before the compact/match loop (`:61-68`), and `EffectExecutor` reverse-pushes so lowest-id applies first (`EffectExecutor.cs:105`).
- **AC3.4** The `EffectNodeJsonConverter` learns `require_tag` at **both** sites: Read `case KindSearchArea` (`:237-249`) — add `"require_tag"` to the `RejectUnknownProperties` allow-list (`:239`) + `ReadEnum<UnitTag>(el, "require_tag", …, required: false, fallback: UnitTag.None)`; and Write `case SearchAreaEffect` (`:122-128`) — `WriteEnum(writer, "require_tag", …)` **omit-when-None** (the 2.5a "Write is the exact inverse of Read" round-trip contract). `require_tag` is a **single enum string** (`"Mechanical"`), not a JSON array — `JsonStringEnumConverter` reads a flags enum from a single (comma-)string.

### AC4 — Tag-conditional counters expressed in the closed vocabulary (epic AC4)

**Given** an effect authored as "+X bonus vs Mechanical" and a separate "Heal only Organic" **When** each resolves against a target that does / does not carry the required tag **Then** the bonus is applied (matching-tag) or **fully omitted** (non-matching), and the heal lands on `Organic` targets **only** — with all gameplay deltas computed in **16.16 Fixed** (no `float`/`Mathf` in the sim path).

- **AC4.1** Both examples are expressed with the AC3 `require_tag` predicate and **no new node** (the closed vocabulary is exactly 7 kinds — `direct_hp_delta`/`heal`/`damage`/`apply_modifier`/`sequence`/`search_area`/`persistent`; there is **no conditional/guard node**, and AR-8 forbids inventing one):
  - **"Heal only Organic"** = `search_area{ filter:"Ally", require_tag:"Organic", child: heal{amount} }` — non-Organic allies are dropped at the matcher; `HealEffect.Apply` clamps `[0, EffectiveMaxHealth]`, all `Fixed`.
  - **"+X bonus vs Mechanical"** (AoE) = `sequence[ search_area{ filter:"Enemy", child: damage{base} }, search_area{ filter:"Enemy", require_tag:"Mechanical", child: damage{bonus} } ]` — the base search hits everyone; the second re-scans and applies the bonus `DamageEffect` to Mechanical-only. Both damage leaves flow through the ONE `DamageResolver.Apply` path (`max(0, amount × matrix[type][armor] − EffectiveArmor)`, all `Fixed`) — the bonus is a **separate matrix-scaled term**, it does **not** touch/bypass the damage/armor matrix (the axis stays independent).
- **AC4.2** Do **not** add a `bonusVsTag` term to `DamageEffect` or a `require_tag` gate to leaves/`Modifier` (an open-ish scripting hatch by the back door — violates AR-8). Route all tag-counters through `SearchArea` for this story (see D-4 for the single-target case; deferred).
- **AC4.3** The two `SearchArea` siblings in "+X vs Mechanical" are on separate root→leaf paths (each path has 1 `SearchArea`), so `EffectCaps.MaxSearchAreaDepth=2` and `MaxTotalEffectNodes=64` are not exceeded — `EffectBounds.Validate` is unaffected.

### AC5 — Back-compatible None default (epic AC5)

**Given** a unit with **no** `tags` field in JSON **When** it is loaded and spawned **Then** its `TagsOf` entry is `UnitTag.None`, it is matched by **no** tag predicate, and it loads without error (back-compat default).

- **AC5.1** `ParsedTags` returns `UnitTag.None` for `null`/empty `Tags` (NOT an `All`-style fallback — the critical divergence from `ParsedAttackDomains`, which returns `All`). No existing faction JSON is edited, so no shipping unit gains a tag by omission.
- **AC5.2** `EntityWorld.Create()` defaults `TagsOf[id] = UnitTag.None` (`:544`, mandatory recycle-reset — the free-list reuses slots; a recycled slot must not inherit the prior occupant's tag, the 1.12/1.13/2.6 SoA-recycle defect class). Every non-def spawn path (`RestoreUnit`, `StressTest`, the `def == null` fallbacks) correctly inherits `None`.

### AC6 — Determinism & no regression (epic AC6, reconciled with the fold-timing rule — see D-1)

**Given** two identical replays of a scenario exercising a tag-filtered `SearchArea` + a "bonus vs Mechanical" effect **When** a `SimChecksum` is taken after resolution **Then** the checksums are **byte-identical** across both runs **And** the tag-consuming path's determinism is proven by a **new golden** (its already-folded `Health`/target-selection outputs are byte-identical across replays) + `ApplyUnitDefinitionGuardTest` coverage of `TagsOf`.

- **AC6.1 (BAKED DEFAULT = NO-FOLD, D-1).** `TagsOf` is **authored-immutable → NOT folded** — the `AttackDomainOf`/`CategoryOf`/`DamageTypeOf`/`ArmorTypeOf` posture (all combat/effect-read authored fields, **none** folded; `SimChecksum.cs` references none of them). `SimChecksum.AlgoVersion` stays **8**, `CanonicalModelHash` stays **3**, the known-state pin `0x983D39AE` is unchanged, `VersionStampConsistencyTests` passes **8/3/1/2 + "0.1"**, and **all 15 existing goldens are byte-identical**. A divergent authored tag changes which target an effect hits → the affected entity's already-folded `Health`/`ModifierStore`/`Position` moves → caught **transitively** (determinism holds without the fold — the epic's "byte-identical replays" clause is satisfied either way). **This reinterprets the epic's literal AC6 "the tag array is folded into SimChecksum" — see D-1; Alec confirms.**
- **AC6.2** New coverage lands as a **new** golden (`tag-filter-scenario`) exercising `require_tag: Mechanical` + bonus-vs-Mechanical + heal-only-Organic over a mixed-tag synthetic set (folded `Health`/target outputs make it a non-vacuous byte-identical replay — the 2.9a discharge pattern), plus `ApplyUnitDefinitionGuardTest` `TagsOf` assertions — **never** by editing the existing 15. Golden count 15→16 (append-only, LF-only per `CrossPlatformGoldenGuardTests`).
- **AC6.3** `TagsOf` is **NOT** added to `SimChecksumCoverageGuardTest` (that guard asserts a field *moves* the checksum; an unfolded field there fails — the explicit `2-9a-*.md:105` instruction). It is NOT added to `ScenarioUnit`/`CanonicalModelHash` either (that hash folds unit *placement*, not `UnitDefinition` stats — `2-9a-*.md:188`).
- **AC6.4 (ALTERNATIVE = FOLD, only if Alec honors the epic literally, D-1).** If FOLD is chosen: one atomic commit like the 7→8 `EffectiveArmor` precedent — bump `SimChecksum.AlgoVersion` 8→9 + add `hash = Mix(hash, (int)world.TagsOf[i])` in the ascending-id entity loop (beside `StatusFlagsOf`, `SimChecksum.cs:150`); re-pin `ExpectedV8Hash → ExpectedV9Hash` (new hash from a green v9 run) + rename `KnownWorldState_ProducesPinnedV8Hash` + `Assert.Equal(9, AlgoVersion)` (`SimChecksumCoverageGuardTest.cs:112,120`); bump `ExpectedSimChecksumAlgoVersion` 8→9 (`VersionStampConsistencyTests.cs:51`); add a `TagsOf` teeth block to `EntityCommandFields_AreFoldedIntoTheChecksum`; and re-record **all 15** goldens (LF). All-or-nothing — a missed step leaves a red guard.

## Decisions

**Baked in (deterministic-rule / minimal-slice calls — applied, not re-asked):**

1. **`UnitTag` is a distinct `[Flags] byte` enum in `src/Core`, default `None`, multi-tag allowed.** Mirrors `AttackDomain` exactly minus the `All` member. Multi-tag OR-fold (a unit can be `Organic|Magical`); the `SearchArea` predicate is **intersection** (match if any required bit is set — AC3's "intersects"). `require_tag` is a single enum string.
2. **The tag predicate is a NEW `RequireTag` field on `SearchAreaEffect`, NOT a `TargetFilter` bit** — `TargetFilter : byte` is full (all 8 bits). Default `None` = match-all (back-compat; every existing `SearchArea` byte-identical).
3. **`ParsedTags` is lenient; the validator rejects.** The accessor OR-folds recognized tokens and returns `None` for unknown/empty (like `ParsedAttackDomains`); the closed-set located reject is a separate validator concern (AC2). This is the deliberate split the codebase already uses (`AbilityDefinition.ParsedTargeting` returns null → `AbilityValidator` rejects located).
4. **Tag SoA follows the A2 single-mapper rule.** `TagsOf` is written ONLY in `ApplyUnitDefinition` (`:620`) and defaulted `None` in `Create()` (`:544`); never hand-copied in a spawn path. Guarded by `ApplyUnitDefinitionGuardTest` (the substitute for a checksum fold). `UnitTag.cs` in `src/Core` is auto-covered by the `SimSources.props` `src/Core/**` glob (2.9a confirmed `AttackDomain.cs` needed no manual add — `2-9a-*.md:324`).
5. **AC4 counters route through `SearchArea(require_tag)` — no new node.** "Heal only Organic" = one `search_area`; "+X vs Mechanical" = a two-`search_area` `sequence`. AR-8-clean, checksum-neutral, all math in the existing `Fixed` `DamageEffect`/`HealEffect` deltas.
6. **`RestoreUnit`/`StressTest` leave `TagsOf` at the `Create()` default `None`.** Both carry no def and correctly inherit `None`; do **not** widen `UnitSnapshot` (out of scope — the documented editor-only Category/AttackDomain restore-fidelity gap at `EntityPlacer.cs:1122-1125`; Story 2.13's field-identical-restore AC lists `tags` → **2.13-owned**, note only).

**Needs Alec's confirmation (recommended defaults baked so the dev can start; see the summary after this file):**

- **D-1 (DETERMINISM — FOLD vs NO-FOLD): recommend NO-FOLD.** Epic AC6 (`epics.md:1121`) + the brownfield note (`:1125`) literally say "the new tag array is folded into SimChecksum … WILL RE-BASELINE the golden." But `TagsOf` is **authored-immutable** in this story's firm scope (nothing in-scope mutates a unit's tags mid-match — the effects *read* tags to filter/counter), which is exactly the shape the standing **[[chimera-checksum-fold-timing-rule]]** (fold only when an array first becomes **mutated mid-match**) and the near-identical **2.9a `AttackDomainOf`** precedent (shipped NOT folded, AlgoVersion stayed 8, goldens byte-identical, guarded by `ApplyUnitDefinitionGuardTest`) both say **NOT to fold**. Determinism holds either way (the tag's only effect lands on already-folded `Health`/`Modifier`/`Position`, caught transitively). All **6** recon analysts independently converged on NO-FOLD. **Recommended: NO-FOLD** (AlgoVersion 8, pin `0x983D39AE`, 15 goldens byte-identical + 1 new tag golden = 16; guard via `ApplyUnitDefinitionGuardTest`) — this reinterprets AC6's literal fold clause to the 2.9a AC3 shape. **Alternative:** honor AC6 literally and FOLD (AlgoVersion 8→9, re-pin, re-baseline all 15 goldens for defense-in-depth) — worth it only if Alec anticipates a near-future story adding **tag mutation** (e.g. a "transmute to Mechanical" / "purge Magical" effect), at which point the fold-timing rule says fold **then**. Tasks 1–7 are written for the NO-FOLD default; AC6.4 is the FOLD checklist.
- **D-2 (VALIDATOR VEHICLE): recommend a fail-closed located drop in the pre-pass, no new `Validated<T>` mint.** AC2 says the bad token is rejected at "the `Validated<T>` gate," but **no `UnitDefinition`/`FactionDefinition` validator exists today** — `ScenarioValidator` gates scenario *placement* only, `AbilityValidator` gates abilities only, and the faction loader (`FactionDefinition.LoadFromFile`) is lenient (no `Disallow`, no converters). A full `FactionValidator` is an Epic-5.2 deliverable (`epics.md:1723`). **Recommended (minimal slice):** a small `UnitTagValidator` (Godot-free, `src/Core/Definitions`) that returns a located `ValidationResult`-style error, invoked in the resolve pre-pass beside `ResolveAbilities`, dropping the bad unit — this satisfies AC2's behavior ("rejects with a located error" + "no spawnable entity") **without minting a new `Validated<T>` type** (avoids editing the `ValidatedMintingTests.cs:49-53` sole-minter allow-list and avoids pre-empting Epic 5.2). **Alternative:** mint `Validated<UnitDefinition>`/`Validated<FactionDefinition>` (most literal to "the `Validated<T> gate`") — then the new file **MUST** be appended to `ValidatedMintingTests.cs:49-53` in the same commit or the source-scan build fails.
- **D-3 (EXAMPLE CONTENT): recommend synthetic test unit only — do NOT edit shipping faction JSON.** Mirrors 2.9a Decision #6: prove the mechanism with a synthetic tagged unit in a dedicated test scenario + the new golden; keep `alpha_faction.json`/`beta_faction.json` untouched in 2.11 (heavy roster tagging is content, belongs with the Epic-3 editor / Epic-5 faction pass). **Alternative (if demo content is wanted):** a minimal sensible assignment — `Mechanical` = `siege_engine` + `war_machine` (constructs; the war_machine is "de-sinned — machines are not homunculi", `fma-faction-design.md:141`), `Magical` = `mage`/`rune_caster` (the Magic-damage casters), `Organic` = the living roster (workers, melee, ranged, air beasts, Court homunculi). Under NO-FOLD even shipping-JSON edits are golden-neutral, but synthetic-only is cleanest.
- **D-4 (SINGLE-TARGET COUNTER SCOPE): recommend SearchArea-only for 2.11; defer the direct-target gate.** AC4's "+X vs Mechanical" is naturally area-based; a **single-target** (`TargetUnit`) "+X vs Mechanical" has no `SearchArea` to filter through. Options: accept a **radius-0 `SearchArea`** self-search idiom (works — `QueryRadius` includes the center at `excludeId=-1`; subtle, can also catch a co-located unit), or add a per-leaf/per-`Modifier` `require_tag` gate (a larger closed field + converter + validator change). **Recommended:** ship SearchArea-only for 2.11 (minimal, closed); defer the direct-target tag gate unless Alec wants it now.

### Current state — precise, source-verified (HEAD 82c0204)

**Data model (`UnitDefinition.cs`).** Three orthogonal combat facets exist — `damage_type`→`ParsedDamageType` (`:235-241`), `armor_type`→`ParsedArmorType` (`:244-251`), `category`→`ParsedCategory` (`:267-275`) — plus the 2.9a `attack_domains`→`ParsedAttackDomains` (`:138-139, :282-300`), the exact `string[]?`→`[Flags]` template. **No tag field exists** (grep-confirmed). **Deserialization path (lenient).** `UnitDefinition` loads **only** through `FactionDefinition.LoadFromFile` → `JsonSerializer.Deserialize<FactionDefinition>(json, JsonOptions)` (`:99-115`), where `JsonOptions` = `Skip comments + AllowTrailingCommas` — **no `Disallow`, no `JsonStringEnumConverter`, no `FixedJsonConverter`**. Consequences (the dual-path DTO constraint, [[chimera-dual-path-content-dto-constraint]]): the `tags` field **must** be `string[]?` (an enum-typed field would throw — STJ reads enums from numbers by default on this path); back-compat is automatic (a missing key leaves `null`); and the loader does **not** reject `["Undead"]` (so AR-8 rejection cannot come from the loader — Task 5). ### Determinism notes (NO fold — `AlgoVersion` stays 8, 15 goldens byte-identical; D-1)

- **`TagsOf` is NOT folded.** It is authored-immutable and effect-read — exactly like `AttackDomainOf`/`CategoryOf`/`DamageTypeOf`/`ArmorTypeOf`, **none** of which appear anywhere in `SimChecksum.cs` (grep-confirmed: `CategoryOf` appears only in comments explaining its exclusion, `:21,:60,:127-129`; `AttackDomainOf`/`DamageTypeOf`/`ArmorTypeOf` appear zero times). `SimChecksum` folds `Effective*` **outcomes**, not authored inputs. A divergent authored tag changes which target an effect hits → the affected entity's already-folded `Health`/`ModifierStore`/`Position` moves → caught **transitively** (`SimChecksum.cs:127-130` rationale). This is [[chimera-checksum-fold-timing-rule]] (fold only when an array first becomes **mutable** mid-match) — tags are dormant in this scope.
- **The tag-consuming effects add no fold.** The heal/damage/modifier a tag-filtered `SearchArea` applies land on `Health`/`ModifierStore`/`Effective*` — **already folded** (v6/v8). No new folded SoA field is introduced.
