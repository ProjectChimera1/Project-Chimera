# Story 3.1c: Composite + feedback components, tooltip/switch foundations, and demo gallery

Status: ready-for-dev

## Story

As a creator-tools developer,
I want the composite and feedback components (menu/tooltip/dialog/toast/spinner/mark/switch) plus a gallery scene that instantiates the full kit,
so that the design-system is visually verifiable in-engine and every later editor composes from one complete, on-brand kit.

## Context & Scope — read first

**This is the third and final pure-presentation story of the UI design-system arc.** **3.1a** authored the token vault (`main.tres`) + the two mechanisms (chamfer, accent). **3.1b** built the 13 *simple* components (the `ChimeraComponents` factory + 3 stateful classes). **3.1c (this story)** builds the 7 *composite/feedback* components that carry the **popover / modal-scrim / animation machinery 3.1b deliberately excluded**, plus the **polished demo gallery** proving the UX-DR33 compose-from-kit guarantee. **Story 3.3 (the read-only Unit Card panel) and everything after it depend on 3.1c** — this closes the kit.

**Like 3.1a and 3.1b, this touches NO simulation code.** There is **no `SimChecksum`, no golden, no fold, no `AlgoVersion` bump, no determinism fence, no stamp movement**. None of the Epic 1/2 machinery applies. If you reach for a checksum test, you are in the wrong story. Tier-1 (Godot-free xUnit) **cannot** instantiate a Godot `Control`/`Theme`, and `godot/tests/` has **no GdUnit4 harness** (verified) — so **`/godot-verify` on an in-engine gallery scene is the sole practical gate**, exactly as in 3.1a/3.1b (Epic 2 retro §5). Tier-1 stays at its carry-forward **~667 pass / 1 skip / 0 fail**; you add **zero** tests to it.

**What 3.1c delivers (the whole story):**
1. **7 composite/feedback components** styled only from the 3.1a Theme: **menu** (UX-DR23), **tooltip** (DR26), **dialog** (DR27), **toast** (DR28), **spinner** (DR29), **mark** (DR30), **switch** (DR31) — the components that carry popover, scrim, and animation machinery.
2. The **tooltip foundation** (UX-DR53 / NFR-2 / UX-DR45): attachable to *any* control, revealing on short-hover **and keyboard focus**.
3. The **switch foundation** (UX-DR54): a clean on/off toggle reusable for simple/advanced disclosure and inline field reveal.
4. A **polished `component_gallery` scene** instantiating **every** component across **3.1b + 3.1c** — the visual proof that the full kit composes on-brand (UX-DR33), replacing the throwaway 3.1b `component_preview` as the canonical demo.

**What 3.1c explicitly does NOT do (scope fences — do not cross):**
- **Does NOT restyle any existing panel** (`AbilityEditorPanel`, `SettingsPanel`, `ContentBrowserPanel`, `CommandCardSystem`, `LobbyUi`, `TriggerEditorPanel`, `MapGeneratorPanel`, `MainMenuOverlay`, `MatchChatOverlay`, etc.) and **does NOT set the project-global default theme** (`project.godot` `gui/theme/custom`). Applying the kit to the shell is **3.11**; to editor panels is **3.3–3.7**. Build the components; leave application to the stories that own it.
- **Does NOT wire any component to real game/sim data.** The `banner-stall` toast shows the MP-stall *visual* only; wiring it to an actual lagging peer is **Epic 11 / Story 11.x**. The switch's "reveal dependent fields" is demonstrated with placeholder fields in the gallery; real hero/advanced fields are **3.4+**. The tooltip is attachable but attaching it to *every* editor control is each editor's job (3.3+).
- **Does NOT re-build the `segment` disclosure control** — the Simple/Advanced **segment** pill-group already shipped in 3.1b (`ChimeraTabs`, `TabsVariant.Segment`). The **switch** (DR31) is the complementary *boolean* primitive for UX-DR54, not a re-do of the segment.
- **Does NOT deliver the light theme** (UX-DR37) — dark theme only, as in 3.1a/3.1b.
- **Does NOT modify `main.tres`, `ThemeTokens.cs`, or `ThemeBuilder.cs`.** Every token 3.1c needs already exists: **`speed`=130** (motion), **`shadow_pop`** (popover elevation), **`accent_glow`** — all three are declared/baked but had **zero consumers** in 3.1b; 3.1c is what activates them. If you believe a token is genuinely missing, **log it (UX-DR33)** and raise it — do not silently add one.
- **Does NOT modify `AccentController.cs`.** Unlike 3.1b (which folded two assigned 3.1a fixes into it), 3.1c has **no assigned Theme-layer fix**. The one temptation — extending `AccentController.AccentProperty` (Fill/Border) to cover an accent *shadow/glow* — is **explicitly out of scope (D-1)**: the procedural `mark`/`spinner` read accent tokens live in `_Draw` and re-read on `AccentChanged`, so they retint (glow included) with **no** controller change; the stylebox popovers use a neutral `shadow_pop`, which needs no accent glow.

## Acceptance Criteria

**AC1 — all 7 composite/feedback components exist as reusable, Theme-styled components.** Each of UX-DR23, DR26, DR27, DR28, DR29, DR30, DR31 (menu, tooltip, dialog, toast, spinner, mark, switch) exists as a reusable component (factory method or thin component class under `ProjectChimera.UI.Components`), instantiable by a caller in one call, and styled **only** from the 3.1a Theme (`main.tres`) read through `ThemeTokens` constants + the `"Chimera"` theme type. Each realizes its spec'd variants/states per the **Per-Component Spec Table**.

**AC2 — no hardcoded color or size that exists as a token.** Every color comes from `ChimeraComponents.Col(token)` (→ `GetThemeColor(token,"Chimera")`), every global spacing/cut from `Const`, every font/size from `FontOf`/`SizeOf`. Component-intrinsic dimensions that are *not* tokens (switch 42×24, knob 18, toast width 300 / accent-bar 3px, tooltip max-width 240/200, menu min-width 180, spinner 22/48/96, dialog width `min(560,90%)`, per-component micro-cuts) are named constants added to `ComponentMetrics`, documented from the CSS spec — **not** inline magic numbers.

**AC3 — tooltip foundation: hover AND keyboard-focus, on any control (UX-DR26/53/45, NFR-2).** A reusable helper attaches a tooltip to **any** `Control` and reveals it on **short-hover** *and* on **keyboard `FocusEntered`** (not mouse-only — this is the UX-DR45 requirement Godot's built-in tooltip does not satisfy), dismissing on leave / `FocusExited`. The tooltip renders **above** the target, `surface_3` bg + `shadow_pop` + `line_strong` inset hairline, faceted (cut 4), with the **bold term in `accent_bright` + `font_display`** and a plain body sentence (UX-DR65 "teach never scold"). It appears **without stealing focus** from the focused control.

**AC4 — switch foundation: clean faceted on/off toggle for disclosure (UX-DR31/54).** The switch is a **42×24 faceted track** (`surface_4` off → `accent` on) with an **18×18 faceted *square* knob** (`text_mid` off → `accent_ink` on) that **slides** (left 3→21) over **130ms** (the `speed` token — "toggles snap"). It exposes a clean boolean API + a `Toggled(bool)` signal, is keyboard-operable (built on a toggle `Button` → focus + Space), and drives **inline reveal** of dependent fields (demonstrated in the gallery, e.g. a "Promote to Hero" row revealing placeholder leveling fields). The knob is a **faceted square, never a round dot** (brand has no radii except `.kbd`).

**AC5 — motion is mechanical, and reduced-motion is honored (UX-DR29/44/50).** Transitions are quick + mechanical: **130ms** `cubic-bezier(0.4,0.1,0.2,1)`-style for switch/tooltip/dialog fades (read the `speed` token); the **toast slides in from the left over ~250ms**; the **spinner** rotates its ring CW (~2.6s), triangles CCW (~5.2s), and pulses its core (~1.3s). **All animation is gated behind a single `ChimeraMotion.ReducedMotion` flag** (default off; the seam a later Settings/UX-DR44 story wires) — when set, the spinner stops/attenuates and transitions become instant. Animations use Godot `Tween`/`CreateTween` (or `_Process`), never a busy loop.

**AC6 — the accent switches across the WHOLE kit (3.1b + 3.1c) in one op.** In the gallery, one `AccentController.SwitchAccent` (teal → amber → violet) retints **every** accent-bound surface across the entire instantiated kit with **zero stale surfaces**: 3.1b's accent surfaces (already proven) **plus** 3.1c's — menu `is-active` text, tooltip term, dialog accent border/foot, toast **default** accent bar, switch **on**-state track+knob, and the procedurally-drawn **spinner** + **mark** (which re-read accent tokens on `AccentChanged` → `QueueRedraw`). Accent styleboxes register via `SharedAccentBox`; accent text/icons via `BindAccentColor`; procedural draws via `SubscribeAccentChanged` → `QueueRedraw`. Semantic bars (toast `--danger/--warn/--ok`, `banner-stall` warn) correctly do **not** move.

**AC7 — UX-DR33 compose-from-kit, proven and logged.** The gallery instantiates **every** component from **both** 3.1b and 3.1c using only the kit's public API (no new primitive invented ad-hoc in the gallery). If building the 7 gap surfaces' needs surfaces a genuinely-missing primitive, it is **logged** (in the Dev Record + `deferred-work.md`), per UX-DR33 — not silently added. The `.select` dropdown popup (a 3.1b-punted item, `Controls.cs:207-209`) is styled here as part of the menu work.

**AC8 — clean scope + in-engine proof.** No simulation file, no checksum/golden, no existing panel or shell restyled, no `project.godot` `gui/theme` change, no global default theme set, no light theme. `main.tres` / `ThemeTokens.cs` / `ThemeBuilder.cs` / `AccentController.cs` / `ChimeraStyleBox.cs` **unchanged**. `dotnet build godot/godot.csproj` → **0 errors** (no new warnings). `/godot-verify` **PASSES** on the new `component_gallery` scene: all 3.1b + 3.1c components render; chamfers faceted (kbd + tooltip 4px are the small-radius/faceted contrasts, knob is a faceted square); the whole-kit accent switch retints teal→amber→violet with zero stale surfaces; switch animates + reveals; dialog is modal over a scrim; a toast slides in + auto-dismisses; the spinner rotates; a tooltip appears on focus. `git diff --stat` stays within `godot/src/UI/Components/**`, the new gallery scene, and workflow tracking.

## Decisions (recommended defaults — confirm with Alec)

Following the Epic 2 / 3.1a / 3.1b recommended-default pattern. Each is the recommendation; take as written unless Alec vetoes. **D-1 (mark/spinner rendering) and D-4 (tooltip trigger model) are the two most worth Alec's attention** — they shape the hardest components.

- **D-1 (mark + spinner rendering) — draw both procedurally in `_Draw`, reading accent tokens live; do NOT import SVG textures and do NOT extend `AccentController`.** *(Recommended.)* The `mark` (Chimera Seal) and `spinner` (transmute) are multi-layer, multi-accent-shade SVGs in the mock (`theme.js`). Rendering them as `Control` subclasses that draw with `DrawArc`/`DrawColoredPolygon`/`DrawPolyline`/`DrawCircle` reading `Col(Accent/AccentDim/AccentBright/AccentGlow)` gives **perfect accent fidelity for free**: on `AccentChanged` the component calls `QueueRedraw()` and re-reads the tokens (glow included) — something a baked stylebox shadow cannot do, which is exactly why 3.1b omitted accent-glow and why **no `AccentController.AccentProperty` extension is needed**. The exact vertex geometry is transcribed in the Per-Component Spec Table so no re-derivation is required; pixel-perfect SVG parity is **not** the AC (the AC is "exists, retints, `.triad` variant"). **Alternative (documented, Alec may prefer):** bundle the SVGs as `.svg` files under `assets/ui/` (Godot imports SVG→texture) and layer `TextureRect`s. Simpler to author but **accent retint is limited to `modulate` (a single multiply color)** — it cannot reproduce the ring/arc/core three-shade accent split, and would need pre-authored per-accent variants or a re-import. Rejected as the default for accent-fidelity; keep as fallback if procedural draw proves too fiddly for the seal.
- **D-2 (menu + `.select` dropdown) — a `PopupPanel` container holding a VBox of themed menu-item Buttons.** *(Recommended.)* `PopupPanel` (a `Popup`) gives **native above-everything layering, positioning near the trigger (`Popup(Rect2I)` / `PopupOnParent`), and close-on-outside-click for free**, while letting us put arbitrary themed content inside — so we chamfer the panel (`cut_sm`, `surface_2`, `shadow_pop` + `line_strong` inset) and build items with the factory's styling (hover `surface_4`+`text_hi`, `is-active` = `accent_bright` text). Give the 3.1b `Select()` dropdown the **same look** (not the same node) by styling its internal native `PopupMenu` via `optionButton.GetPopup()` — a chamfered `panel` stylebox + `hover` stylebox + font colors — closing the `Controls.cs:207-209` punt. **Alternative:** native `PopupMenu` (free keyboard nav + submenus, but its per-item accent-text active-state is awkward and its theming is more rigid than a VBox we fully own). Rejected as default; the menu content in the mock is a simple hover-list, so the VBox path is both simpler and more on-brand.
- **D-3 (dialog modality) — custom `CanvasLayer` + full-rect `ColorRect` scrim + centered chamfered `PanelContainer`, focus-trapped; scrim blur approximated as a solid dim.** *(Recommended.)* Matches the in-repo overlay precedent (`MainMenuOverlay`/`SettingsPanel`/`ContentBrowserPanel` all use `CanvasLayer`), gives full chamfer control (`cut_lg`=14, `shadow_pop`, an `edge_light`→`line` hairline approximated as a single `edge_light` border), and lets us **eat input** (`scrim.MouseFilter = Stop`) + **trap focus** (`GrabFocus` on open; `SetFocusNeighbor` wrap on the foot buttons; `Esc` closes). The CSS `backdrop-filter: blur(2px)` is not cheaply available for a `ColorRect` (needs a `BackBufferCopy`/shader) → **approximate with a slightly-more-opaque solid scrim** (`rgba(6,8,11,~0.8)`), a documented spec-sanctioned approximation like 3.1b's gradient→solid fills. Head/body/foot layout + right-aligned foot buttons (gap `s3`) + explicit-confirm-for-destructive (a `danger` primary). **Alternative:** `AcceptDialog`/`ConfirmationDialog` (`Window`-based — free modal/focus/Esc) — rejected because the `Window` frame is hard to chamfer to brand and it fights the code-built-UI convention.
- **D-4 (tooltip trigger model) — a manual popover shown on BOTH hover (short-delay `Timer`) and `FocusEntered`, via a `ChimeraTooltip.Attach(control, term, body)` helper; NOT Godot's `_MakeCustomTooltip`.** *(Recommended.)* Godot's built-in custom tooltip (`Control._MakeCustomTooltip(string)`, confirmed present in 4.6, returns an `Object`) is **mouse-hover-only** and requires **subclassing the target control** — so it cannot serve "tooltip on *any* control" and cannot satisfy UX-DR45 (keyboard focus reveals). Instead, `Attach(ctrl, term, body)` connects `ctrl.MouseEntered`(+a short hover `Timer`)/`MouseExited` **and** `ctrl.FocusEntered`/`FocusExited` to one show/hide path that pops a single themed tooltip `Control` on a high overlay `CanvasLayer`, positioned above `ctrl` — appearing **without stealing focus** (a plain Control, *not* a `Popup`, which would grab focus and break the focus trigger). **Alternative:** use `_MakeCustomTooltip` for rich hover tooltips + a separate focus path — rejected (two mechanisms; still needs subclassing for the hover half). One uniform path is simpler and meets both triggers.
- **D-5 (switch) — a custom `ChimeraSwitch : Button` (toggle_mode) with faceted styleboxes + a `Tween`-animated square knob; NOT `CheckButton`.** *(Recommended.)* `CheckButton` is Godot's native switch but skins its toggle via **`Texture2D` icons** (round, pre-rendered) — it cannot produce the brand's **faceted square knob** or retint from tokens. Build on a toggle `Button` (inherits **focus + Space-to-toggle + `Toggled(bool)`** for a11y/UX-DR45) with a chamfered track stylebox (`surface_4`→`accent`, register the on-state fill) and a **knob child** (faceted-square `StyleBoxFlat`, `text_mid`→`accent_ink`) animated `left:3→21` over the `speed` token via `CreateTween().TweenProperty(...)`. Stateful class (static `Create` + `Build`, `[Signal] Toggled`), a `RevealTarget`/callback wires inline field disclosure. **Alternative:** `CheckButton` with custom checked/unchecked textures — rejected (textures aren't token-driven, break accent retint, wrong shape).
- **D-6 (toast) — a `ChimeraToastHost` on a high `CanvasLayer` managing a top-left VBox stack; `Show(title,msg,variant,duration)` slides in + auto-dismisses.** *(Recommended.)* Host node owns the stacking container (top-left, column, gap `s2`=8, width 300 per the mock `.alerts`), and `Show(...)` instantiates a faceted toast (`surface_2`, `cut_sm`, `shadow_2` + `line_strong` inset, **3px full-height left accent bar** recolored per variant), slides it in from the left (~250ms `Tween` on `Position`+`Modulate`), then after `duration` fades + `QueueFree`. Variants `--danger/--warn/--ok` set the **semantic** bar color (fixed tokens, not accent); the **default** bar is `accent` (register for retint). Include the **`banner-stall`** sibling (a centered warn pill + a warn-tinted `sm` spinner) as the MP-stall visual (UX-DR28/64 hook; wiring is Epic 11). **Alternative:** individual toasts each own a `Timer` with no host — rejected (the host centralizes stacking + reduced-motion gating).
- **D-7 (motion + reduced-motion) — read the `speed` token (130ms) for control transitions; use the mock's per-component durations for toast (250ms) + spinner (2.6/5.2/1.3s); gate ALL motion behind a static `ChimeraMotion.ReducedMotion` flag.** *(Recommended.)* The "130ms" rule is **not universal** (agent-confirmed: toast slide is 250ms, `.f-tip` fade 120ms, spinner has its own loop durations). Read `speed` for switch/tooltip/dialog; hardcode the CSS-specified toast/spinner durations as `ComponentMetrics` constants. Add a `static bool ChimeraMotion.ReducedMotion` (default `false`) that the spinner + toast + transition helpers check — the forward-correct seam for the not-yet-built accessibility setting (UX-DR44). **Alternative:** ignore reduced-motion for now — rejected (UX-DR29 explicitly "gates on prefers-reduced-motion"; a static flag is ~5 lines and forward-correct).
- **D-8 (component home + delivery) — new own-file component classes under `godot/src/UI/Components/`, plus a `ChimeraComponents.Feedback.cs` partial for any stateless factory pieces; extend `ComponentMetrics`.** *(Recommended.)* Mirror the 3.1b split (D-2/D-6): stateful/animated/popup components each get a file — `ChimeraSwitch.cs`, `ChimeraDialog.cs`, `ChimeraToastHost.cs` (+ toast row), `ChimeraMenu.cs`, `ChimeraTooltip.cs`, `ChimeraMark.cs`, `ChimeraSpinner.cs` — under `ProjectChimera.UI.Components`, `#nullable enable`, `partial` on Godot-derived classes. Any purely-stateless factory helper goes in a new partial `ChimeraComponents.Feedback.cs` (mirrors `.Surfaces.cs`/`.Controls.cs`). New intrinsic dims → `ComponentMetrics.cs`. **Alternative:** one big file — rejected (the per-file convention is established and cleaner).
- **D-9 (gallery scene) — a NEW `component_gallery.tscn` + `ComponentGallery.cs` showing the FULL 3.1b + 3.1c kit; the 3.1b `component_preview` is left as-is (or optionally retired).** *(Recommended.)* Reuse the `ComponentPreview.cs` scaffold pattern verbatim (load `main.tres` via `ResourceLoader…CacheMode.Ignore` → `new AccentController` → `ChimeraComponents.Initialize` → `ScrollContainer`/`VBox` + `BuildXxx(col)` sections + `Heading`/`Row`/`Body`/`WithLabel` helpers + the accent-switch button row). Add sections for the 7 new components (with interaction triggers as **Buttons whose `pressed` signal `/godot-verify` can emit** — open-dialog, show-toast, toggle-switch — since godot-mcp has **no absolute-mouse click**). This is the canonical UX-DR33 demo. **Alternative:** extend `component_preview` in place — rejected (it was declared throwaway; a fresh polished gallery is the 3.1c deliverable, and keeping the 3.1b proof intact avoids churn).

**Notes / gotchas (all verified against the mock + engine):**
- **Motion is NOT universally 130ms** — toast slide is **250ms**, `.f-tip` fade 120ms, spinner has its own loop durations. Read `speed` for control transitions; hardcode the others as `ComponentMetrics` constants (documented).
- **`StyleBoxFlat` has NO gradient fill** — the dialog `surface_2→surface_1` gradient and the mock's accent gradients port as **solid** fills (the 3.1b-sanctioned approximation). The dialog's masked `edge_light→line` two-layer border ports as a single `edge_light` hairline.
- **No `backdrop-filter: blur`** cheaply in Godot for a `ColorRect` — approximate the scrim blur with a slightly-more-opaque solid dim (D-3).
- **Tooltip must NOT be a `Popup`** — a `Popup` grabs focus and closes on focus-loss, which breaks the keyboard-focus trigger (UX-DR45). Use a plain `Control` on a high `CanvasLayer`.
- **`menu` is a dropdown popover**, not a right-click context menu (grep of the mock: zero `contextmenu`). **`switch` ≠ `segment` ≠ `tabs`**: the `segment` pill-group (the Simple/Advanced *disclosure UI*) already shipped in 3.1b (`ChimeraTabs.TabsVariant.Segment`); the `switch` is the *boolean primitive*; both feed UX-DR54.
- **Semantic vs accent:** toast `--danger/--warn/--ok` bars + `banner-stall` use **fixed semantic tokens** (never retint); only the **default** toast bar + menu `is-active`/tooltip term/switch-on/dialog-accent are **accent** (register/subscribe).
- **`mark`/`spinner` accent-glow works via procedural redraw** — `SubscribeAccentChanged` → `QueueRedraw` → `_Draw` re-reads `accent_glow` live. This is the ONLY way to get an accent-following glow without extending `AccentController` (a baked stylebox shadow can't) — and it's why D-1 chooses procedural draw.

### Overlay / z-order strategy (the machinery 3.1b lacked — verified absent)
The 3.1b kit has **zero** Popup/Tween/scrim/z-order code (grep-confirmed). 3.1c introduces all of it:
- **`PopupPanel`** (a `Popup`) for **menu** + the `.select` dropdown — native above-everything layer, positions near trigger, closes on outside-click. OK to take focus.
- **High `CanvasLayer` (≈100+, above the base UI's ≈14)** for **tooltip** (plain Control, no focus-steal), **dialog** (scrim + panel), **toast host**. The in-repo `CanvasLayer`-overlay precedent (`MainMenuOverlay.cs:29`, `SettingsPanel.cs:20`, `ContentBrowserPanel.cs:27`) is the shape to copy — but those panels are hand-styled and predate the kit; do **not** modify them, just mirror the layer approach.
- **`Tween`/`CreateTween`** (confirmed 4.6 API: `CreateTween()` → `TweenProperty(obj, "position"/"modulate"/"rotation", finalVal, dur)`, `.SetTrans`/`.SetEase`, `.Parallel()`/`.Chain()`, `.SetLoops()`, `.TweenInterval(sec)`, `.TweenCallback(Callable.From(...))`; the old `Tween` *node* is gone in 4.x). Every animation routes through `ChimeraMotion` for the reduced-motion gate.

### Anti-patterns to avoid (LLM-dev traps)
1. **Rounded corners** anywhere. Every surface goes through `ChimeraStyleBox.Chamfer` (faceted). The switch knob is a **faceted square**, not a round dot. (Only `.kbd`, a 3.1b component, is radiused.)
2. **Literal colors/sizes.** Read every value via `Col/Const/FontOf/SizeOf`; new intrinsic dims → `ComponentMetrics`. A baked literal fails AC2 and (if accent) won't retint.
3. **Forgetting the accent seam.** Accent styleboxes → `SharedAccentBox`; accent text/icons → `BindAccentColor`; procedural draws → `SubscribeAccentChanged`→`QueueRedraw`. A baked accent value left un-refreshed is the AC6 failure.
4. **Modifying Theme-layer files.** `main.tres`/`ThemeTokens.cs`/`ThemeBuilder.cs`/`AccentController.cs`/`ChimeraStyleBox.cs` are **untouched** this story (unlike 3.1b, there are no assigned Theme fixes). `speed`/`shadow_pop`/`accent_glow` already exist — consume them.
5. **`_MakeCustomTooltip` for the tooltip.** It's mouse-only + needs subclassing → can't do "any control" or keyboard-focus (UX-DR45). Use the manual `Attach` path (D-4).
6. **`CheckButton` for the switch.** Its toggle is a round `Texture2D` icon, not a faceted token-driven square (D-5). Build on a toggle `Button`.
7. **A `Popup` for the tooltip.** It steals focus and breaks the focus trigger. Plain Control on a `CanvasLayer`.
8. **Extending `AccentController` for glow.** Not needed (D-1) and out of scope — procedural redraw handles it.
9. **Scope creep.** No restyling existing panels, no global default theme, no light theme, no wiring to real sim/MP data, no touching sim/checksum/golden.
10. **Godot-C# gotchas (3.1b-earned):** fully-qualify **`Godot.Theme`** (namespace shadow); `BoxContainer` property is `Alignment`, enum is `BoxContainer.AlignmentMode` (not `…Enum`); qualify nested enums from sibling classes (`ChimeraComponents.TabsVariant`); use `System.Math.Clamp/Round` on `double` (Godot `Mathf` is float-only); `GD.Print` not `Console.WriteLine`; `partial` on every Godot-derived class; theme item names use **underscores** (never hyphens).
