## 3. What Hurt — ranked by severity

### 3.1 🟠 "Gated" is not "verified" — the gates prove reachability plus a subset of ACs

Each gate is honest about its own edges, which is the right posture. Read together, though, the caveats form a pattern worth naming before anyone quotes "in-engine verified" in a release conversation:

- **11.2** — online-branch asymmetry (menu doesn't pause; Speed/Save/Load disabled) not exercised; crystal/razed counters read 0 because the match generated none
- **11.3** — the online Save/Load-disabled arm not exercised (needs a dedicated server + peer)
- **11.4** — the under-attack toast/SFX path was verified at the **gate** level (`IsInView`) and the **toast** level, *never end-to-end from a real off-screen combat event*; MP ping replication is code-reviewed only. The camera and toast fixes are Godot `Node`/`Control` code outside the Tier-1 link set — **no automated regression net at all**.
- **11.5** — a populated buff row was not exercisable: GDScript cannot construct the C# `Modifier`. (The confirming pass later did drive one live `matter_infusion` icon.)
- **11.7** — reflow sampled 1080p + scale 1.5 only, against an AC naming a 1080p/1440p/4K × 2-scale matrix; live apply / safe-revert Keep-path have no automated regression net "per the intent's own verification contract"

So the gate is a **reachability-and-smoke** gate. That is worth enormously more than three epics of nothing, and it caught five real defects — but it is not an acceptance gate, and the difference should stay explicit.

*Decision (Alec, this retro): **leave the gate as-is.** It is earning its keep and additional ceremony would slow it without a demonstrated need. The residual is accepted and recorded here rather than fixed.*

### 3.2 🟡 The gate is brittle — 11.6 spent a whole repair session on colon placement

11.6's evidence line read `- asserted (authoring source ...):`. The script's regex is `^\s*-\s*asserted:`. A genuine, fully-quantified in-engine record — machine-unparseable. The repair session's handback is candid: it declined to re-drive the scenario because doing so would "re-photograph already-verified numbers at real risk of a spurious FAIL against correct code," and instead re-verified every captured number against `alpha_faction.json` by hand.

A gate that fails correct work on formatting trains people to route around it. Per §3.1 this is accepted for now — logged so that if it recurs, the second occurrence is a pattern and not a surprise.

Upstream [bmad-loop#304](https://github.com/bmad-code-org/bmad-loop/issues/304) / PR #274 remain unmerged, so the *sweeper* half is genuinely blocked on someone else. But the *appender* half is ours, and "blocked upstream" has now been the answer across four retros while the invisible pile grew.

Items worth naming so they don't drown in volume:
- **11-6:** supply-cap overshoot on queue-ahead — `HasSupply` recomputes from live units and is never incremented by enqueue, so five enqueues all see the same headroom. Impossible at depth-1; introduced by the depth-5 widening.
- **11-6:** a unit authored with `TrainTime <= 0` makes a head whose timer is 0, which `TickProduction` skips forever — now blocking four slots behind it. No validator enforces `TrainTime > 0`.
- **11-7:** `MigrateForward` stamps `CurrentSchemaVersion` unconditionally, so a `settings.json` written by a newer build is silently downgraded and its forward-only fields dropped. Pre-existing since 8.1; real cross-build data loss.
- **11-4:** the `CombatEventQueue` 256-ring can silently drop denial/completion cues under heavy combat burst — no non-hit priority.
- **11-4:** the P2P `SendMapPing` path trusts the wire faction byte (spoofable; only the server path re-stamps).

*Response: A1-E11 — patch the appender locally (Alec's decision this retro).*

### 3.4 🟡 Traceability improved, and the root cause is now proven rather than inferred

3 of 6 stamped `final_revision`s are HEAD-reachable — against **0 of 15** last epic. The split is not random:

- **Resolve** — 11.1 (`a9a65d9`), 11.2 (`7a84845`), 11.5 (`c7c1b78`): stories committed directly to the branch
- **Dangle** — 11.3 (`c43eee2`), 11.6 (`3ad0f69`), 11.7 (`08d981f`): stories bmad-loop **squashed**. All three objects exist in the repo; none is reachable from HEAD. The stamp is taken from the pre-squash commit.
- **11.4** — no `final_revision` field at all

That is A4-E9's root cause demonstrated live: the stamp fires before the squash. The **re-attached half held cleanly** — all seven `baseline_revision`s are HEAD-reachable and not one came from a mid-run `[AutoSave]` commit (the 9.3/9.7 relapse did not recur; there were no `[AutoSave]` commits in range at all).

### 3.5 🟡 The action-item tracker is write-once

All seven Epic-9 `action_items` in `sprint-status.yaml` still read `status: "open"` — including **A1-E9**, which was built, wired, and is the single biggest win of this epic; **A2-E9**, executed 2026-07-25 and written up in the Epic-9 retro's own §10 addendum; and **A3-E9**, whose sweep ran and whose partition was committed at `f7f747a`.

Standing rule A1-E5 exists so items cannot evaporate. We honour it on **filing** and not on **closing**, which means the tracker's status column carries no information. Combined with `epic-11: backlog` sitting above seven `done` stories for a fourth consecutive epic, the pattern is: *the artifacts that record state are updated when a story is created and never again.*

### 3.6 🟡 A6-E7 was honored reactively for the second straight epic — on the story named as its test

Epic 9's retro was explicit: *"Epic 11's 11.3 save/load is its next real test — 11.3 ships its wiring guard in the implementing pass, not a review pass."*

It did not. Review found the byte-identical proof "covered only the economy slice — the golden scenario exercised no deaths/heroes/items/research/projectiles/DSL, so ~half the restore paths ran on default data," and added the missing resume tests. The genuinely load-bearing regression test (`SaveLoad_ResumeByteIdentical_WithMidMatchBuiltBuilding`) came from the post-merge ultra-review, one layer later still. The item's success criterion — *written by dev, not retrofitted by review* — was not met.

### 3.7 🟡 Five of seven specs carry `multiple-goals` and `oversized`

11.2 absorbed four originally-separate stories, 11.3 two, 11.4 two. The cost shows in the review record: 11.1 needed four review passes plus a gate FAIL to converge; 11.3 needed a sixth (post-merge) layer to catch a HIGH in folded state; 11.4's triage log spans a review pass, an ultra-review, two follow-up fix rounds, and a deferred-findings burn-down. The merges were the 2026-07-01 correct-course's deliberate consolidation and they did ship — but the epic is evidence that a merged story costs review passes, not just dev passes.

### 3.8 🟡 Epic 15 was sequenced to interleave with Epic 11. Zero Epic-15 stories ran.

The 2026-07-28 correct-course put Epic 15 (ledger burn-down + FR-79 reconnect, 13 stories) on an interleave with Epic 11 — it is written in the comment directly above the `epic-15` block in `sprint-status.yaml` and in the Epic-9 retro's sequencing note. Nothing interleaved.

This is the second consecutive epic in which a **recorded sequencing decision was silently not followed** (Epic 9's §3.7 was the inverse case: Epic 11 was sequenced before Epic 9 and Epic 9 ran first). Different direction, identical failure mode — and combined with §3.3 it means the burn-down is now further behind than when it was scheduled.

### 3.9 ➖ A5-E9's accepted risk played out exactly as written

Epic 11 built the entire session shell on a multiplayer rail that has still never talked to a second machine. Every MP-touching arm is code-reviewed only: concede riding the order stream, MP ping replication and its ally filtering, online Save/Load gating, the online in-match menu asymmetry, `LockstepManager.EnqueueConcede` (Godot/ENet-coupled, excluded from Tier-1). The FR-39 two-machine LAN gate — the #1 pre-ship gate, carried since Epic 1 — remains un-run.

Not a failure: this was Alec's recorded call at the last retro, taken knowingly. Recorded again so the cost stays visible when Epic 10 arrives.

**Verdict.** Epic 11 is the epic where the project stopped shipping blind.

Seven stories built the entire session layer — a real setup screen, a staged load driven by the actual phase spine, true single-player pause, deterministic game speed, concede riding the order stream, a checksum-verified full-world save/load, the whole FR-74 feedback floor, depth-5 production with refunds, and live video settings behind an honesty invariant — while moving exactly one golden set, on a fold that was scheduled five epics ago and arrived on time.

But the headline is not the shell. It is that **the fix we built last epic finally bit.** Epic 9's retro concluded that a capability nobody is required to use does not exist, and prescribed making in-engine verification load-bearing. A1-E9 did that, and Story 11.1 — after three clean review passes — went to the gate and failed with a defect that quietly deleted the opponent's entire army on any cross-faction launch. Four more stories were caught the same way: a save that restarted from tick 0, a minimap rendered off the screen, glyphs that would have printed as tofu, a quality setting that did nothing.

None of those are visible in a diff. All of them are obvious the moment the game runs.

The unfinished half is the same shape it has always been: the things we made mechanical held, and the things we left to discipline slipped. Two action items fully landed this epic — a script with an exit code, and a bounded session with a checklist. The ledger appender, the traceability stamp, the tracker's status column, and the wiring-guard habit all sat one layer below that bar, and all four regressed or stalled. Epic 15 is a burn-down epic; it will succeed or fail on exactly that distinction.
