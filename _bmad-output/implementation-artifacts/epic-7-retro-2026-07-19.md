## 2. What Went Well

1. **Determinism discipline scaled to six SimChecksum folds and seven CanonicalModelHash folds without a single unauthorized golden move.** Every fold was one named re-baseline in one commit; the Block-If tripwires (does this move CMH/SSH? does the expression layer move a baseline?) were evaluated and correctly *not* tripped by the four stories that added no sim state (7.1, 7.2, 7.4, 7.10). The sharpest artifact is 7.13's **differential-guard-as-gate**: after two unattended HALTs on re-baseline safety, the `/bmad-loop-resolve` converted the judgment into a checked invariant — a frozen v20 control scenario that must move exactly as predicted — and mandated a **checksum-neutral-slice-first commit discipline** (land the non-hash-moving code, then the bump + re-baseline as an isolated commit). That recipe (differential guard above a green suite; SimChecksum byte-identity holds only for zero-trigger goldens; CanonicalModelHash folds must be omit-when-default) is now proven and reusable.

2. **Adversarial review carried the epic — it caught every "green tests, dead feature" and every vacuous test.** The signature defect class this epic was *code that passes the whole suite while doing nothing*: 7.9's null-lockstep write rail (every button a silent no-op behind 2456 green tests), 7.3's host wiring deletable without a red test, 7.15's wiring line droppable while green, 7.4's hardcoded `Faction=0`. And a matching class of **tests that asserted nothing** — 7.2's vacuous+shallow round-trip tripwire, 7.9's local-action guard that never referenced its own parameter, 7.11's CMH fold test with no teeth, 7.15's trivially-true differential guard. **Not one of these was caught by dev self-report; all were caught by the 4-layer review reasoning**, and each was closed with a regression test that genuinely turns red on deletion.

3. **The loop recovered from real infrastructure failures without losing work.** 7.6 hit two consecutive verification timeouts and was rescued by warm-starting from a preserved attempt snapshot (not a rebuild) + raising `session_timeout_min`. 7.5's implementation stranded in dangling worktree snapshots, got recovered and hand-re-landed across the diverged 7-6/7-7/7-8 line — the exact scenario the "diverged-sibling re-land" recipe exists for — landing at reconciled SimChecksum v18 / CMH v10. Both are proof the loop's failure-recovery paths work; both are also arguments for the traceability tooling that would make them cheaper (§3.4).

4. **A5-E6 was honored in full — the pre-Epic-7 gate actually happened.** Epic 6's retro committed that the 14-1…14-5 remediation batch must land before Epic 7. Ground truth: 14-1 (`e54bda9`), 14-2 (`766ca42`), 14-3 (`f6a78bd`), 14-4 (`f28dbaf`), 14-5 (`544fd90`) **plus** the pulled-forward hard gates 14-7 (`8d70a7e`) and 14-8 (`6eb3c36`) all committed 2026-07-15 — hours-to-a-day before 7-1 opened at 07-16 03:06. Epic 7 started green (7.1 baseline: 1796/1/0). The scheduled-key discipline from Epic 6 held.

5. **Mid-epic infra fixes were folded in cleanly, not deferred.** The A4-E3 CRLF golden divergence (a long-standing cross-platform landmine) was closed at the serializer chokepoint (`577b3eb`) during the run; the determinism-gate CI SDK pin and the shared-runner perf ceiling were both fixed inline (`4cee14e`, `3c1ee8a`). The epic cleaned up load-bearing CI debt while building on top of it.

## 3. What Hurt — ranked by severity

### 3.1 🔴 "Green tests, dead feature" was the epic's signature failure — and one shipped inert to the last review
7.9's custom-UI **write rail was completely dead in the running game**: `CustomHudOverlayPhase` (phase 10) captured `SceneContext.Lockstep` by value 13 phases before `MatchLifecycleController` creates it, so `_lockstep` was permanently null and **every button press was a silent no-op** — invisible to all 2456 passing tests, and the story was marked `done` with the manual in-engine check un-run. It was caught only because two independent review layers reasoned about the phase ordering. The same shape recurred as latent holes in 7.3 (production host wirings deletable without a failing test), 7.15 (drop the `SimulationHost`→director wiring line, suite stays green, overlay shows zero fires forever), and 7.4 (hardcoded `a.Faction=0` passed every test because every execution test used Global targets). **The root cause is structural: production wiring seams between the sim stores and `SimulationHost`/`MainScene` have no headless coverage, so deleting the wire compiles and stays green.** Several stories added a "delete-the-wire-turns-red" teeth-test *reactively* after review flagged it. *Response: make it standing — A6-E7 (production-wiring smoke). And the artifact-referenced done-gate (A1-E7) is the structural stop for "marked done, never actually run."*

### 3.2 🔴 Story 7-5 broke one-squash-per-story — stranded, recovered, and re-landed out of order, mutating its own determinism footprint
7-5's implementation was lost to dangling worktree-snapshot commits (`c7472a1b`, `9d2c7e84`), never reaching master; a downstream 7-6 run tripped on the dirty tree and the missing 7-5 surface. The orchestrator re-sequenced **7-5 after 7-6/7-7/7-8** and hand-merged the recovered commit (`8c36cfe` → re-land `1597e4d` → flip `eb75385`). The cost: 7-5's determinism plan changed from spec — intended SimChecksum **16→17** became **17→18** (folding after 7.6's `DslLoopState`), and its spec'd CanonicalModelHash *exclusion* **inverted to a v10 fold** because 7.7's v8 whole-model fold had already dissolved the Triggers-basis exclusion. This is the single biggest spec-vs-shipped determinism delta in the epic, and it was reconciled only in a terse frontmatter `merge_note`, not a dev-record narrative. It worked — but it depended on a human doing careful cross-branch surgery, and 7-9's blocking sweep then **false-negatived** on it (grepped *guessed* API names, found "zero code," declared 7-5 unimplemented when it had in fact landed green on both platforms). *This is the strongest evidence for the traceability + done-gate tooling (§4 / A1-E7).*

### 3.3 🟠 The UI epic shipped its UI unobserved — again
In-engine `godot-verify` ran for only **7.4 (full)**, **7.11 (partial, follow-up)**, and **7.15 (partial)**. The other 12 stories — including every custom-UI surface — went out on code-reading, pattern-conformance, and "boots clean." **Three stories still carry `followup_review_recommended: true` at close: 7.8 (read rail — explicitly requests a live per-player-scoreboard pass for both Player 1 and Player 2), 7.10 (T3 editor — twice-recommended, the interaction surface is drag-bound and the harness can't do absolute-position mouse drags), and 7.11 (LOST-latch/grace-rescope semantics want independent confirmation).** The one confirmed dead feature of the epic (7.9, §3.1) lives precisely on this unobserved surface, proving the blind spot bites exactly as it did in Epic 6. *Response: a consolidated pre-Epic-8 in-engine verification session (A2-E7) over the write rail, read rail, T3 editor, win-condition preset playtests, and the objectives overlay — clearing the three standing flags + DW-178/180/182/190.*

### 3.4 🟠 Traceability stamps orphaned again — the Epic 6 A6-E6 gate never landed, and it bit twice
Both 7-5 and 7-9 recorded a **`final_revision` that points to a worktree-snapshot hash no branch contains** — `git checkout` from HEAD cannot resolve them. 7-9 also left an uncommitted `sprint-status.yaml` flip in the tree. This is A3-E5 / A6-E6 recurring verbatim: post-squash hashes aren't stamped from the reachable commit, and there is no gate stopping it. One `[AutoSave]` commit (`82b84b4`) also landed inside the Epic 7 range — benign this time, but exactly the content-commit path A4-E5/A6-E6 was meant to guard. *Response: A1-E7 schedules the post-squash traceability stamp + content-commit guard (A6-E6, sharpened) for pre-Epic-8.*

### 3.5 🟠 Ledger hygiene regressed mid-epic and burn-down was ~+20 / −1
Stories 7-9 through 7-12 used the proper numbered format (DW-176…DW-190), but **7-13 and 7-14 regressed to flat un-numbered bullets** (5 items, no id/status) — the same regression Epic 6 flagged in §3.5, from the same cause (no sweep ran to normalize the intermediate append state). Only **DW-185** burned down within the epic (7.11 filed it, 7.12 closed it via the `AllianceStore` fold). DW-175 (determinism/CRLF residuals) stays open; the flat-bullet tail is un-triageable until swept. *Response: A4-E7 — run the bmad-loop sweep to number the tail and partition the ~175 open set before Epic 8 adds more.* (Note: DW-139, an Epic 6 open follow-up, was closed 2026-07-16 by human decision — a small contradiction with the A7-E6 note that it "stays open for a human pass"; recorded here for continuity.)

### 3.6 🟡 sprint-status was never closed for Epic 7 and its action-item statuses drifted
`epic-7` sat `backlog` the entire epic despite all 15 story keys reaching `done`; `epic-7-retrospective` was `optional`; `last_updated` froze at 2026-07-15.
