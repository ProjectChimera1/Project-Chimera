## Intent

**Problem:** Trigger conditions are a flat pure-AND list (`AllConditionsMet`) and `set_variable` writes only literal Int values — no OR/NOT/grouping, no arithmetic, no computed right-hand sides, and the non-Int types 7.3 made declarable (`Fixed`/`Bool`/`Point`) are storable but unusable. FR-24's "arithmetic/boolean expressions" half is missing, so creators cannot express `(gold >= cap && !done) || count(2) < 5`-class logic.

**Approach:** Add a CEL-shaped, pure, typed, side-effect-free expression sublanguage as a strict extension of the graph IR: five new closed-registry expression node kinds (`expr_literal`, `expr_var`, `expr_unary`, `expr_binary`, `expr_call`) wired by typed data edges (wire color = type; `DataWireType` gains `Int`/`Fixed`/`Point`). Two-phase: at load an `ExprCompiler` type-checks, rejects literal-zero divisors, and cost-caps every expression subgraph into a flat, preallocated, Fixed/int-only postfix `ExprProgram` (located errors at the `ScenarioValidator` gate); in the tick a zero-allocation evaluator runs the pre-checked program. Expression roots gate triggers through the existing Boolean condition-in port (enabling OR/NOT/grouping) and feed `set_variable` through a new value-in data port (enabling typed Int/Fixed/Bool assignment). A Godot-free CEL-shaped text parser (`ExprParser`) compiles editor-authored expression text into the same IR subgraph — the T2 authoring surface; raw-IR stays the advanced hatch.

## Boundaries & Constraints

**Always:**
- All new sim/DSL code (`src/Dsl/Expr*`) is Godot-free and float-free: fractional numerics are `Fixed` 16.16 via `Fixed.Raw` int math; the text parser converts decimal literals (e.g. `1.5`) to `Fixed.Raw` with pure integer/long arithmetic — **never** `float.Parse`/`double`/`Fixed.FromFloat` — using `InvariantCulture`-safe char digits.
- Closed grammar exactly: binary ops `+ - * / %` (mod), comparisons `> < >= <= == !=`, boolean `&& || !`, unary `-`, grouping `( )`, literals (Int `123`, Fixed `1.5`, Bool `true/false`), declared-variable reads (`name`, per-player `name[k]` with integer-literal slot k), and built-ins `count(faction:Int)->Int`, `distance(a:Point,b:Point)->Fixed`, `min/max(a,b)` (Int,Int)->Int / (Fixed,Fixed)->Fixed, `abs(a)` Int->Int / Fixed->Fixed. Nothing else parses; unknown identifiers/ops/fns are located rejects.
- CEL-shaped strict typing, checked at load: no implicit Int↔Fixed promotion (mixed `Int + Fixed` is a located type-mismatch reject, as is `Bool + Fixed`); arithmetic requires both operands Int or both Fixed; comparisons require same numeric type (`==`/`!=` also Bool==Bool) and produce Bool; `&& || !` require Bool. `==`/`!=` on Fixed compare exact raws (the legacy `variable_comparison` epsilon applies only to the untouched legacy leaf).
- Total, deterministic runtime semantics (the pre-checked program can never throw in the tick): a runtime divisor/mod-by-zero evaluates to 0 (both Int and Fixed); `abs(int.MinValue)` → `int.MaxValue`; Int overflow wraps unchecked; no short-circuit side-effect semantics needed — expressions are pure, both branches may evaluate.
- Expressions live in the graph IR only (no flat `TriggerDefinition` schema change): an expression root gates a trigger via a `Boolean` data edge into the existing `TriggerConditionInPort` (ANDed with any legacy `ConditionNode`s, matching multi-condition semantics), and feeds `set_variable` via a new `ActionValueInPort = 1` data edge whose wire type must equal the declared target variable's type (Int/Fixed/Bool targets only). Expression-bearing triggers persist to `ScenarioData.TriggerGraphJson` (the run_effect precedent).
- Two-phase contract: `ExprCompiler` runs at BOTH the `ScenarioValidator` pre-tick gate (located `ValidationResult.Fail`, fail-closed) and `ScenarioDirector.LoadScenario` (compile-once into programs held per trigger). Compile rejects, each with a located error: type mismatch, literal-zero divisor (`expr_literal` value 0 wired into `/` or `%` right operand), undeclared variable name, `name[k]` on a non-PerPlayer variable or bare `name` on a PerPlayer variable, TriggerLocal-scoped reads in a **condition** expression (7.3 P4 rule extended), `EntityRef`/`FactionRef`/`TimerRef`/`Array`-typed variable reads, missing/forked operand edge (exactly one data edge per operand port), wire-type ≠ inferred type, op-count over `ExprBounds.MaxExprOps`, and depth over `ExprBounds.MaxExprDepth`. `expr_var` per-player slots pass the same `CheckFactionSlot` gate other graph nodes get.
- Evaluation is zero-per-tick-allocation: programs are flat postfix int-op arrays with stacks preallocated at compile; `count` reaches the world through a small Dsl-owned interface (e.g. `IExprWorld { int CountAlive(int factionSlot) }`) implemented by `ScenarioDirector` (ascending-id scan, existing `CountAlive` semantics); `distance` computes exactly like `FixedVec3.Distance` over (X, 0, Z) raws.
- Any new node kind/field extends `NodeKinds`, `NodeBaseJsonConverter` Read+Write allow-lists (fail-closed stray/duplicate/unknown), and the validator's graph gate in lockstep; new `DataWireType` members serialize NAME-only (existing `Boolean` name untouched). Canonical serialization (nodes by id; edges by tuple) must round-trip expression subgraphs byte-identically.
- Named caps are constants in one place (`ExprBounds`: e.g. `MaxExprOps = 64`, `MaxExprDepth = 16`, `MaxExprTextLength = 512`) — documented as corpus-validated dials, never inline literals.

**Block If:**
- Any golden checksum baseline, `CanonicalModelHash`, or `StartStateHash` moves — 7.4 adds **no new sim state** (expression writes land in the already-folded `DslVarTable`; `AlgoVersion` stays 16); movement means expression machinery leaked into hashed state or serialization of expression-free scenarios changed. HALT with status `blocked`, condition `expression layer moved a checksum/hash baseline`.
- Wiring the expression evaluation into `ScenarioDirector` changes observable tick behavior for any legacy (expression-free) scenario — a determinism/parity/golden test diverges. HALT with status `blocked`, condition `expression wiring is not behavior-parity for expression-free scenarios`.

**Never:**
- No loops/`ForEach`/array population/fuel counter (7.6); no custom events/`RaiseEvent` (7.5); no authoritative structural graph validator — dangling/forked **exec** edges, duplicate ids stay 7.7 (forked/missing **operand data** edges are compile errors here only because the compiler cannot function without that check); no T3 visual node canvas (7.10); no new read-accessor leaves beyond the five built-ins (entity HP/position etc. are 7.13).
- No expression wiring into EventNodes, event thresholds, or any ActionNode field other than `set_variable`'s value-in port. No `Point`-producing operators and no Point/EntityRef/FactionRef/TimerRef/Array assignment targets.
- No float/double anywhere in the expression path (parse, compile, eval); no `System.Random`/wall-clock; no Dictionary enumeration in compile output ordering or eval; no `[JsonPolymorphic]`; no second effect/trigger executor; no `SimChecksum` fold changes and no `AlgoVersion` bump.
- Do not modify the flat `TriggerDefinition`/`TriggerCondition`/`TriggerAction` POCOs or their JSON schema — the flat channel stays frozen; expressions are graph-channel-only.

## I/O & Edge-Case Matrix

| Scenario | Input / State | Expected Output / Behavior | Error Handling |
|----------|--------------|---------------------------|----------------|
| OR/NOT/grouping condition | Trigger gated by expr root of `(a \|\| b) && !c` (declared Bool vars), authored as text and as raw-IR | Trigger fires exactly per boolean semantics; legacy ConditionNodes on the same trigger still AND with the expr result | No error |
| Computed set_variable RHS | `set_variable(score)` with value-in edge from `(gold + 5) * 2` (all Int) | On fire, `score` = evaluated Int; a Fixed-typed target assigns from a Fixed expr (raw-exact); Bool target normalizes to 0/1 | No error |
| Type mismatch | Expression `flag + 1.5` (Bool + Fixed), loaded via validator gate | Rejected at load | Located error naming the node id and both types |
| Literal-zero divisor | `x / 0` or `x % 0` in authored IR/text | Rejected at load (validation), not at runtime | Located error; editor shows it, no trigger added |
| Runtime zero divisor | `a / b` where `b` (variable) is 0 on some tick | Evaluates to 0, tick continues; byte-identical across two headless runs | No crash, no error |
| Cost cap | Expression compiling to > `MaxExprOps` ops (or depth > `MaxExprDepth`) | Rejected at load | Located error naming the cap constant |
| Undeclared / wrong-scope var | Expr reads undeclared `ghost`; or `name[2]` on a Global var; or TriggerLocal var in a condition expr | All rejected at load | Located errors (undeclared name; scope misuse; TL-in-condition) |
| Built-ins | `count(1)`, `distance(p,q)` (Point vars), `min/max/abs` | Typed results per closed signatures; `count` of an empty faction = 0; wrong arg count/type rejected at load | Located errors on misuse |
| IR round-trip | Expression subgraph → `ToCanonicalJson` → `FromJson` → `ToCanonicalJson` | Byte-identical JSON; data edges carry `Int`/`Fixed`/`Boolean` wire names | No error |
| Determinism + no-drift | Seeded scenario with expression triggers run twice headless; full golden suite run normally | Byte-identical `SimChecksum` sequences (`AlgoVersion` 16); zero golden/`CanonicalModelHash`/`StartStateHash` movement | Divergence/movement trips a Block-If |
| Editor text errors | Manual form expression field gets `1 +` or `x ??` or over-length text | Fail-closed on Accept; located parse error on the status label; no trigger/graph change persisted | Located `JsonException`-style message |

## Design Notes

- **Why no checksum movement (vs 7.3's re-baseline):** expressions add compute, not state. Programs are load-time artifacts; every runtime write lands in the already-folded `DslVarTable`. If any golden moves, something leaked — that is the Block-If, not a re-baseline.
- **Why no implicit Int↔Fixed promotion:** CEL rejects cross-type arithmetic; silently promoting Int (32-bit range) into Fixed (±32767 integer range) would corrupt large scoreboard counters. Creators write `5` (Int) or `5.0` (Fixed) to pick the domain; the closed built-in list deliberately omits conversion fns (later vocabulary work if ever needed).
- **Why runtime div-zero → 0:** `Fixed`'s `/`/`%` throw `DivideByZeroException` on zero raw — a deterministic crash is still a crash. The AC mandates load-time rejection of the statically-knowable case (literal 0); a variable divisor needs total semantics, and 0 is the WC3-lineage convention. Both are tested.
- **Fixed-literal parse without float:** split on `.`, e.g. `"1.5"` → intPart 1, fracDigits "5" → raw = (1 << 16) + (5 * 65536 + half) / 10 computed in `long` (round-half-up, cap fraction digits ~5). Reject `NaN`-ish/multi-dot/over-range at parse.
- **Per-player read syntax `name[k]`:** k is an integer literal 0..7 (validator additionally applies the engine `CheckFactionSlot` ceiling). Declared-scope-driven disambiguation keeps this from colliding with 7.6 arrays (Array-typed vars are rejected in expressions entirely this story).
- **Editor pickers:** 7.3 restricted `set_variable` to Int vars because raw literal writes to Fixed vars were a scope leak. The expression path is properly typed, so the picker widens only when a value expression is present.
