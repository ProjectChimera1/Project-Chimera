## 2. What Went Well

1. **The whole creation suite shipped.** Design-system (3-1a/b/c) → Unit Card Editor read/edit/model (3-3/3-4/3-5) → orthogonal composition + promote-to-hero authoring (3-6/3-7) → persistence manifest + hero-picker (3-8/3-9) → **Edit↔Play no-restart loop (3-10, the creation-loop spine)** → items sim + shop + inventory (3-15/3-16) → editor-undo fidelity (3-17). That is the authoring half of the platform, delivered as one coherent kit.

2. **The determinism fence held while three folds landed on top of it.** Each fold (3.12/3.13/3.15) was deliberate, re-baselined, and re-pinned (v12 / `0xAFB46F6A`); **3.14 rode 3.13's reserved fields with no second bump** (the pre-reserve discipline paid off exactly as designed); every no-fold story stayed byte-identical. Epic 1's #1 ship risk is still retired, now through v12.

3. **Prior-retro commitments were delivered.** **A2-E2** (the unit-cost / start-resource bounds validator open since 1.3b) shipped as the Godot-free `UnitDefinitionValidator` in 3-4 — it returns *all* located field errors and closes the negative-`cost_crystal`-adds-crystal and `Fixed`≥32768-overflow defects. **A3** (gate teeth) produced 3-17's `UnitSnapshot` field-coverage guard — the `ApplyUnitDefinitionGuardTest` pattern applied to restore, so a future per-unit field left out of the snapshot goes RED.

4. **Long-running deferred debt got paid.** 3-17 closed the `RestoreUnit`/`UnitSnapshot` fidelity debt tracked across **six** stories in `deferred-work.md` (§1.13/§2.2a/§2.7/§2.9a) — the accumulating "editor undo silently reverts authored state to defaults" class.

5. **Where review ran, it earned its keep.** 3-16's review caught a negative-cost fail-closed hole and a re-minted-stat-item modifier bug, both fixed with oracle tests (`NegativeCost*_FailsClosed_SimGate`, `LoadInto_ReMintedStatItem_AppliesCarriedModifier`). 3-12's review surfaced the projectile-non-convergence leak (logged, chartered to its own change). The 3-layer instinct still finds real bugs.

6. **bmad-loop cleared 12 stories largely unattended.** After the gds→loop pivot, the orchestrator drove dev + (conditional) review + commit for 3-6 through 3-17 with only two human interventions — a genuine throughput gain over hand-running each `gds` step.

## 3. What Was Hard — Patterns & Growth Areas

1. **The review gate regressed — the one discipline Epics 1 & 2 never let slip.** Action item **A1** was "3-layer review on *every* story; Edge Case Hunter never skipped." bmad-loop's `review: recommended` trigger delegates the call to the dev session's self-assessment, and **5 of 12 stories shipped with zero independent review** (3-6, 3-7, 3-9, 3-11, 3-17). *In fairness the skip heuristic was mostly defensible* — it reviewed **every determinism-fold/sim story** (3-12/3-13/3-15/3-16) and the two hardest (3-8/3-10/3-14), and skipped pure authoring/UI. **But** it is implicit, unaudited, and made at least one debatable call: **3-9 is the determinism-adjacent persistence rail** (it mints heroes into `StartStateHash`) and it went out unreviewed. And every commit reads *"implemented and reviewed via bmad-loop"* regardless of whether a review ran — the message overstates the record.

2. **Story 3-4 fell into the toolchain seam.** It is the epic's **highest-risk story** — it writes edited unit data **back to faction JSON on disk** (`FactionWriter` / `SyncFactionUnits`, a `System.Text.Json.Nodes` DOM patch). Yet it sat stranded in `review` while every story built on top of it shipped `done`. Root cause: the gds→bmad-loop handoff. The loop logged the hand-created keys (`3-1a`, `3-4`, …) as `sprint-status-unknown-keys` and never picked 3-4 up — to review it *or* to flip it. Its code is committed and its own story file already read `done`; only the dedicated review and the tracker flag were missing. **Closed this session as a tracking artifact (D-1).**

3. **The loop needed babysitting on the hard stories.** On 3-10 (Edit↔Play) auto-rollback was **off** during the run, so a failed dev attempt demanded a **manual `git reset` three times** (the `rollback-manual-required` / `run-paused` cycle) before it progressed. 3-15 (item fold) auto-rolled-back once then succeeded. A single config choice (`rollback_on_failure = false` at run time) turned transient failures into human gates. **Since corrected — the config now has it `true` (D-3).**

4. **Every story ran hot on tokens.** The `max_tokens_per_story = 2_000_000` budget tripped on **all 12** bmad-loop stories (soft — none aborted), ~143M tokens for the run. That is the practical ceiling on how large a story the loop can swallow before the budget signal fires; Epic 4's table-retirement stories should be scoped with that ceiling in mind.

5. **The suite no longer closes 0-fail.** Tier-1 ends at 1104 pass / 1 skip / **1 fail** — `ProceduralMapGeneratorTests` (WSL↔Windows cross-platform determinism tripwire, Expected 3026392010 / Actual 413099587). Pre-existing and not an Epic 3 regression, but it is a *cross-platform determinism* failure — the exact class the project treats as sacred — sitting unaddressed, and it dilutes the "green suite" signal every future story reads.

6. **The work-type pivot moved verification onto clickable UI.** `/godot-verify` (godot-mcp signal/exec driving) became the primary gate for the editor panels, hero-picker, item shop, and inventory grid. That is sound, but it grows the Epic 2 "parked physical-gesture" backlog: a large new pile of editor gestures verified by signal injection, not by a human clicking through the panels.
