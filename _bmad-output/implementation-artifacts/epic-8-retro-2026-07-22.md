## 2. What Went Well

1. **Cleanest-integrity epic to date.** 0 intent-gaps, 0 bad-spec loopbacks across all five stories, no fabricated pass, no false-`done`, and — unlike Epic 7 — **zero human escalations**. The second consecutive clean-integrity loop epic and the cleanest; the adversarial-review discipline that carried Epic 7 held without needing a single `/bmad-loop-resolve`.

2. **The Epic 7 forward-flag (A5-E7) was applied in full.** 8.3 honored the DSL-schema audit completely: it extended the flat trigger prompt with the five previously-omitted event kinds (`unit_damaged`/`unit_trained`/`ability_cast`/`hero_level`/`player_chat`) + the `unit_in_region` condition, added a **located** `NodeKinds`-membership rejection to `Validate` (unknown *and* graph-only constructs rejected with a path+value error, driven off the same registry the load gate uses), and guarded both with an exact-line-token staleness test. **The meta-lesson held a fourth epic: the commitment lived as story key `8-3`, so it shipped.**

3. **Real security surface, handled cleanly — the project's first secret-handling epic.** Keys came off the plaintext `[Export]` fields onto a `user://secrets/*.key` store that is *structurally unpackable* from the PCK (Godot packs only `res://`); a `SecretExclusionTest` scans the committed source/scene tree and **fails loudly** if a plaintext key field is reintroduced; cloud requests are pinned to a host allowlist; responses are byte-capped; the selected provider is authoritative with **no** silent fallback. The one HIGH of the epic was a security catch review earned: 8.2's shared `HttpClient` followed redirects, and .NET does **not** strip the custom `x-api-key` header on a cross-host 302 — an allowlisted host could 302 into exfiltrating the Anthropic key. Fixed with `AllowAutoRedirect=false` (and 8.3 applied the same hardening to `LLMService`'s owned client). Adversarial review paying for itself exactly where it matters most.

4. **Determinism footprint was correctly zero — by reuse, not a new path.** The load-bearing safety decision across 8.4/8.5: generated content quantizes where hand-authored content already does (abilities via `ContentJson.Options`/`FixedJsonConverter` at parse; units/heroes/factions at the unchanged `EntityWorld.ApplyUnitDefinition` boundary), so a generated/applied stat hashes identically to a hand-authored one *by construction*. No second float→Fixed path and no bare-definition hash were introduced — both explicitly forbidden and both honored.

5. **Adversarial review still caught the Epic-7 defect classes.** The "green tests, dead feature" and "vacuous test" hunting carried: 8.2's byte-cap test passed on *shape* rejection rather than the cap (Verification Gap rewrote the fixture so only the cap can fail it); 8.5's `SetField` snake_case→property switch was asserted for only 3 of 23 tunable fields — a wrong-property copy-paste would silently persist the wrong stat, all green — closed with a data-driven `[Theory]` over all 23 + a `SetField`-coverage guard; 8.4's faction per-unit ref-check was inert in production (panel passed null registries) — caught and wired to a real `AbilityRegistry`. Not one was caught by dev self-report; all by the 4-layer review.

6. **Compounding architecture.** The `RunDraftAsync<T>` pipeline (8.4) and the one-closed-vocabulary-three-consumers pattern (8.5's `TunableFields` feeding prompt + validator + apply-mapper so they *cannot* drift) show each story building on the prior frozen surfaces — the "8.1/8.2 surfaces must fit as-is" Block-If held every time, and 8.5 needed *zero* new phase wiring because 8.4 had already threaded the AI deps.

## 3. What Hurt — ranked by severity

### 3.1 🟠 The AI UI shipped unobserved in-engine — Epic 7 §3.3, verbatim — and this time it includes the key-entry surface
Every one of the five stories shipped Godot-coupled UI the headless harness cannot reach — the Settings AI-provider four-state panel + masked key entry, the Test-connection "Transmuting…" spinner, the three entity-editor draft affordances (Unit Card incl. hero toggle, Ability, Faction Definer), and the balance-suggestion rows — and every story's residual-risk section carries the identical sentence: *"left for manual verification, outside the headless harness, same boundary as 8.1–8.x."* None of it was driven in-engine. **The stakes are higher than Epic 7's unobserved scoreboards: this is the UI where a creator types their API key and reads the four-state availability verdict.** Epic 7's one confirmed dead feature (7.9's null write rail) lived on exactly this class of unobserved surface. The load-bearing Godot-**free** logic (adapters, factory, allowlist, cap, evaluator, validate routers, `TryApply`, prompt staleness) is fully Tier-1-covered — which is why the blind spot didn't bite this epic — but the wiring seams (phase→panel `Initialize`, spinner, four-state label, editable-draft landing, key snapshot/restore state machine) are unverified. *Response: A1-E8 — the pre-Epic-11 in-engine verification of the Epic 8 AI surfaces, now folded into the native-Windows-bmad-loop migration (§5) that fixes this class at the root.*

### 3.2 🟠 The A1-E7 traceability tooling still isn't built — proven by a live git check, and the class recurred (benignly)
All five Epic 8 `final_revision` hashes (`820376b8`, `929cf744`, `d8aba000`, `5eff6449`, `4b836393`) are **dangling pre-squash commits** — `git merge-base --is-ancestor <hash> HEAD` fails for every one; `git checkout <final_revision>` cannot resolve them from HEAD. This is A1-E7(b) (post-squash traceability stamp) recurring for a **third consecutive epic** (A6-E6 → A1-E7 → open). Unlike Epic 7's 7-5, the recurrence is *benign* — the squash chain is otherwise clean and one-squash-per-story held (each story's `baseline_revision` == the prior story's squash commit). A1-E7(a) (artifact-referenced done-gate): Epic 8 had no *confirmed* false-`done`, but every story was again marked `done` with its manual in-engine check un-run — the exact gap the done-gate exists to close; it didn't bite only because the Godot-free logic was so thoroughly Tier-1-covered. **The meta-lesson holds a fourth epic: scheduled keys ship, Alec-owned loop tooling idles.** *Response: the native-Windows migration (§5) makes the done-gate naturally satisfiable (the loop can attach a real godot-mcp digest); the traceability stamp (b) stays owed regardless of OS — carried as A3-E8.*

Same "the `development_status` key is ground truth; the `action_items` status field is unreliable" pattern flagged in the last two retros. *Fixed at this retro: A5-E7 reconciled to `done`.*

### 3.4 🟡 Deferred-work grew ~+15 and the partition is still owed
Epic 8 filed roughly 15 new defers (8.1:2 · 8.2:1 · 8.3:4 · 8.4:5 · 8.5:3). ## 5. Significant Discovery — Native Windows bmad-loop supersedes the platform-split action items

**Discovery (Alec, 2026-07-22, from the BMAD Discord):** bmad-loop now supports **native stock MS Windows with no WSL requirement** — the blocking dependency (`psmux` v3.3.7, a PowerShell/Windows-Terminal tmux alternative) has been resolved. This is MVP v0.1 of the feature.

**Why this is the root-cause fix, not another band-aid.** The cause under Epic 8's §3.1 (unobserved UI), Epic 7's §3.3, *and* the `ai-active` golden staleness (A3-E7) is one structural fact: **the loop runs in WSL, but Godot/godot-mcp and the Windows-only float `ai-active` golden run on Windows.** A whole class of verification physically cannot happen where the robot works, so it gets punted to manual after-the-fact sessions (A2-E7) that then don't happen inside the loop. A loop running **natively on Windows** collapses that split:
- In-engine verification can become a **per-story loop step** (the loop drives godot-mcp, attaches a state digest as evidence) instead of a one-off manual session — structurally eliminating the §3.1 unobserved-UI debt going into the almost-entirely-Godot-coupled Epic 11.
- The `ai-active` golden stops rotting every fold (recorded/verified on Windows natively).
- A1-E7(a)'s done-gate becomes **naturally satisfiable** — "was the manual check run?" can now be *yes, here's the digest*, rather than a gate that would block everything.

**Decision (Alec, 2026-07-22): migrate to native Windows bmad-loop before the first Epic 11 loop run.** This **supersedes** the manual-session framing of **A2-E7** (for Epic 8's surfaces) and the platform-split half of **A3-E7** by fixing their shared cause.

**Fallback note:** if the native Windows loop is not stable in time for Epic 11, fall back to a **one-off consolidated in-engine verification session** (Claude via godot-mcp, per the A2-E7 recipe) over the Epic 8 AI surfaces — Settings four-state + masked key entry + Test-connection spinner; the Unit/Ability/Faction draft affordances; the balance-suggestion rows — with evidence recorded, before Epic 11 opens.

**Migration risks (from project memory — this is a guarded operation, not a casual reinstall):**
- The setup is destructive (archive+delete `.claude`/`_bmad`/`.bmad-loop`, then `npx bmad-method@next install`). The `@next install` channel is the **same one that silently overwrote committed game content in Epic 5 (story 5.3)** — the reason guardrail (c), the content-commit guard, exists. Snapshot `godot/resources/data/**` and diff-detect after install.
- The installer has misbehaved on this project before ("plain installer HANGS"; "bundled YAML setup scripts UNSAFE on this TOML install" — [[bmad-tooling-update-notes]]).
- Deleting the framework dirs blows away a **rich custom layer that must be restored**: `_bmad/custom/*` (28 skill overrides + `config.toml`), the **gitignored** `config.user.toml` (archive is its only backup), and the `gds-*` module skills (a separate installable the bmad-method @next install may not restore).
- Global `~/.claude` (1.3G) holds Alec's memory system, personal skills, and this session's own environment — **not deleted, only its irreplaceable parts archived.** Project `.claude/settings.json` is Claude Code config (not bmad) — **preserved.**
- Tradeoff to track: the WSL loop was doubling as the free Linux **cross-platform determinism** check. Moving the loop to Windows means cross-platform goldens need a deliberate Linux leg (occasional WSL/CI run) rather than a free byproduct — relevant because Epic 11's 11-3 (checksum-verified full-world save/load) puts determinism back on.
