## Intent

**Problem:** Five latent EntityPlacer/creation-suite defects break authoring fidelity on the multi-select and placement paths that Story 6.1's single-entity sync already handles: (DW-137) editor-placed ground **items** are never mirrored into `ScenarioData.Items`, so they silently vanish on Save/reload and on the F5 Edit→Play re-apply; (DW-151) group move/copy/paste re-derives entities from a thin descriptor, so a moved/duplicated **worker** respawns as a combat unit (loses supply/gather/carry/mesh overrides), a **building** loses its authored `pre_built` flag, and a **resource node** loses its Story-4.7 collection/owner fields; (DW-153) marquee box-select and 3D selection markers unproject/place against a hard-coded `y=0`, so markers sink below Story-6.3 raised ground and selection references flat ground instead of the sim's terrain height; (DW-159) prop place / paste / duplicate / group-move have **no map-bounds guard** (unlike `WaterTool.CommitDrag`), so an off-map placement persists then fails whole-scenario validation confusingly; (DW-163) the start-position editor assumes contiguous 0-based slots, so a validator-legal non-contiguous set (e.g. `{0,3}`) drops the slot-3 marker at load and misroutes the palette P-toggles and "−" remove.

**Approach:** Localized fixes mirroring existing in-file patterns. DW-137: add an `_onItemSync` callback (same `ScenarioSyncOp` opaque-handle protocol) fired in `PlaceItem`'s history closure + a `MainScene.SyncItem` handler over the nullable `Items` array (mirrors `SyncResourceNode`/`SyncProp`). DW-151: enrich `PropDescriptor`/`Describe`/`BuildCreate` — units restore via the identity-preserving `EntityWorld.SnapshotUnit`/`RestoreUnit`, buildings carry the source DTO's `pre_built`, nodes capture+restore the full 4.7 field set (live via the full `_nodes.Create`, persisted via an extended `_onResourceNodeSync`). DW-153: sample terrain height via a new `EntityWorld.SampleElevation(x,z)` (reads the sim `ElevationGrid` `_world` already holds) for the marquee hit-test and the selection markers. DW-159: a `WithinMapBounds` guard (via the existing `_scenarioGetter`) rejecting off-map creates in `PlaceProp`/`BuildCreate`/`MoveSelection`, mirroring `WaterTool.CommitDrag`. DW-163: size/reveal the 3D markers and render the palette toggles by declared slot **value** (from `PlayerSlots[i].Slot`), not by count, with the slot-set arithmetic extracted into pure Godot-free helpers.

## Boundaries & Constraints

## Design Notes

**DW-137 no DeleteItem:** `TryDeleteAt` has no item branch and no `DeleteItem` exists — items are place-only in the editor. The intent is "survive Save/reload," fully closed by syncing `PlaceItem`'s Add/ReAdd/RemoveHandle. Adding delete capability is a separate feature, explicitly out of scope.

**DW-151 units via snapshot:** `EntityWorld.SnapshotUnit`/`RestoreUnit` already replay the caller-owned worker residue (`MeshType`/`GatherState`/`CarryCapacity`/`SupplyCost`) after the def mapper (see `godot/CLAUDE.md`). Reusing them for group-move is strictly better than re-deriving via `DoSpawnCombatUnit` and matches the single-entity delete/undo path. `RestoreUnit` allocates a fresh id via `Create`, which is exactly what move/paste need.

**DW-153 presentation caveat (residual, not a blocker):** `MultiMeshBridge`/`BuildingBridge` currently draw entities at y≈0 and do NOT read `EntityWorld.Elevation`. This fix aligns box-select/markers with the sim's ground-truth `ElevationGrid` (what `Elevation[]` is stamped from), per the intent. Full visual coincidence on elevated terrain additionally needs a presentation mesh-lift, which is a separate concern out of this bundle's scope. On flat maps (every existing scenario) `Sample`=0, so there is zero behavior change — no regression risk to shipped content.

**DW-159 status surface:** EntityPlacer has no on-screen status label (all feedback is `GD.Print`, unlike `WaterTool`'s `_statusLabel`). Use `GD.Print("[EntityPlacer] … outside map bounds (±b) — not placed.")` for the reject message; the load-bearing fix is rejecting the off-map create at place time so it never persists to fail validation later. Adding a shared editor toast is out of scope.

**DW-163 value-vs-count:** The write path (`MainScene`→`ScenarioData.UpsertStartSlot`/`RemoveStartSlot`) is already keyed by `.Slot` value. Only three surfaces are count-derived and wrong for non-contiguous sets: the bridge marker sizing (`ScenarioLoadPhase`), the palette toggle loop, and the "+"/"−" targets (`_startSlotCount±1`). Extracting `DeclaredSlots`/`LowestUndeclared`/`MaxDeclared` as pure helpers makes the arithmetic testable without Godot and keeps the Godot-coupled `RefreshSubRow` thin. Preserve the DW-161 deferred-grow (count grows only on placement, "+"-armed slot rendered as pending) and DW-167 economy coalescing exactly.
