## Intent

**Problem:** Win conditions and scripted goals are invisible to players. There is no objectives model, no `ShowObjective`/`CompleteObjective`/`FailObjective` DSL actions, no in-match quest-log panel, and no pre-match briefing — a scenario can be authored with a win preset and the player never learns what they must do. Objectives are greenfield: no `objectives` field, no objective/briefing surface exists anywhere in the codebase, and the GDD only names `objectives.json` ("player-facing objective descriptions") without prescribing a field schema.

**Approach:** Add an authored `objectives` list to the single monolithic `ScenarioData` model (the GDD's aspirational multi-file `scenario/objectives.json` split is not how the engine loads — everything is one `ScenarioData` JSON). Store live objective **state** (Hidden/Active/Complete/Failed) as reserved `Int` DSL variables in the existing `DslVarTable` so it **rides the v16 DSL-store fold with NO `SimChecksum` bump** (the story's explicit disposition). Add three sim-side action leaves — `show_objective`/`complete_objective`/`fail_objective` — through the closed `NodeKinds` registry per the Story 7.13 add-a-kind checklist; these new node kinds fold into `CanonicalModelHash` (bump 13→14, single `hero-start-state.golden.txt` re-record). A pure `ObjectiveResolver` computes "effective objectives" (authored list, else one default synthesized from the win preset via `WinObjectiveText.For`) deterministically at the `ScenarioApplier.Apply` match-start seam, so every match shows its goal. Presentation adds two code-built `CanvasLayer` overlays: an in-match quest-log (toggle key + new-objective toast) reading objective state through the existing `DslVarReadback` read-rail, and a skippable pre-match briefing (map name/description, objective list, faction blurb) reusable by Epic 13.

## Boundaries & Constraints

**Always:**
- **Objective state rides the existing `DslVarTable` fold — NO `SimChecksum` `AlgoVersion` bump, NO world-golden re-baseline.** Each effective objective declares one reserved `Global` `Int` DSL variable (state ordinal: `0=Hidden, 1=Active, 2=Complete, 3=Failed`) at `ScenarioDirector.LoadScenario`, appended after authored `scenario.Variables` decls in deterministic ascending effective-objective order, seeded from the objective's `initial_state`. The three actions mutate it via the existing `_vars.SetInt` path. This folds via the v16 `DslVarTable.FoldInto` at `SimChecksum.cs:562-565` already present — objective state therefore replays byte-identically with no new folded state and no bump. Reserved objective variables live in a reserved name namespace the validator forbids authored variables from using (so no collision); `SimChecksum.AlgoVersion` stays **21**.
- **Sim purity for the three action leaves and the reserved-var seeding:** no `using Godot`, no `float`/`double`/`Mathf`/`Fixed.FromFloat`, no wall-clock, no string formatting / `int→string` / `Fixed→mm:ss` in the tick. Objective **titles/descriptions are strings and NEVER enter the tick** — the sim carries only the state ordinal (int); strings are interned/handled at the load boundary and rendered presentation-side. Objectives iterate ascending id; the three actions charge fuel (`_loopState.Charge(1)`) like `order_units`/`enable_trigger` since they write folded state.
- **One vocabulary source, no tier drift.** `show_objective`/`complete_objective`/`fail_objective` are declared in `NodeKinds` (`NodeBase.cs`) and propagated through every surface they touch per the 7.13 add-a-kind checklist: node classes + `KindOf` + `NodePorts` (`IsExecIn`/`IsExecOut` single-continuation action group), `NodeBaseJsonConverter` (Read + Write + `RejectUnknownProperties`), `GraphStructureGate` (via `NodePorts`), `DslLoopGate` `WalkChain` cost arm + a `RequireObjectiveTarget` existence check mirroring `RequireTriggerTarget`, `TriggerGraph.IsGraphOnlyKind` + fail-closed `ToFlat`, `NodePaletteFactory` (T3 palette), `ScenarioDirector.ExecuteLeaf`, `CanonicalModelHash` node switch (explicit arm — never the `default` type-name-only fold), `ScenarioValidator` objective-id cross-reference, and the `NodeKindsLockstepTests` master list + round-trip builder. They are **graph-channel-only** (like the 7.13 leaves — NOT added to `ActionTypes`/`FlatActionTypes`); the T2 sentence editor surfaces them via the existing read-only "edit in graph view" fallback. All four tiers are covered: T1 = the default-objective auto-emit from the win preset; T3 = palette + graph authoring; T4/NL = the same load gate; T2 = read-only graph-view row.
- **`CanonicalModelHash` bump 13→14, single golden re-record.** The three new node kinds fold their objective-id semantic field in the `CanonicalModelHash` node switch (an explicit arm each — the `default` arm folds only the type name and would let two objective actions differing only by target collide → MP handshake desync). Bump `CanonicalModelHash.AlgoVersion` 13→14, update `VersionStampConsistencyTests`, and re-record `hero-start-state.golden.txt` (the 7.11/7.13 precedent: a graph-walk extension bumps even though no existing scenario carries the new kinds). A scenario carrying **none** of the new kinds folds **byte-identical apart from the single version integer** — this is the differential guard (below), gating the re-record above a green suite.
- **Authored `objectives` is hash-excluded authoring/presentation data.** The new `ScenarioData.objectives` array (mirroring the `ScenarioVariable` model) is omit-when-null-normalized at the `ScenarioSerializer.Serialize` chokepoint so every existing scenario serializes **byte-identically**, and is **EXCLUDED from `CanonicalModelHash`/`StartStateHash`** (same disposition as `ScenarioVariable` declarations and `display_name`/`description`: declarations stay out of the handshake; only the live reserved-var value folds into `SimChecksum`). Objective id/title/description strings are never folded anywhere.
- **Default objective from the win preset.** A pure `ObjectiveResolver.Resolve(ScenarioData) → ResolvedObjective[]` returns the authored objectives when present, else **exactly one** default objective synthesized from the win condition/preset via a pure `WinObjectiveText.For(WinCondition, WinConditionSpec?)` helper (e.g. `DestroyAllBuildings → "Destroy all enemy buildings"`, one line per built-in + the four `WinPresetKind` presets). Both the sim (reserved-var declaration) and presentation (panel/briefing text) consume the SAME resolver so they agree; the default is deterministic-from-preset (the preset params already fold into `CanonicalModelHash` via `MixWinConditionSpec`). `ObjectiveResolver` and `WinObjectiveText` are Godot-free and live in `src/Core/Definitions/`.
- **Live objective state is read presentation-side via the non-folded read-rail, never the folded store.** The quest-log panel reads reserved objective vars through `DslVarReadback` (double-buffered, version-stamped, explicitly NOT in `SimChecksum` — AR-32) and re-formats a row only on version change (the `CustomUiBridge` pattern). No panel state ever feeds back into the sim; opening/closing the panel leaves `SimChecksum` byte-identical.
- **Both surfaces survive the F5 Edit→Play round trip (Story 3.10).** Objective definitions and briefing text live on `ScenarioData` (re-applied by `MainScene.ResetToAuthoredStart`); overlays use late-bound `() => _ctx.Scenario` getters (the `CustomHudOverlayPhase` idiom) so they survive re-apply. The briefing is presentation-only and does NOT gate the deterministic tick (a lockstep peer cannot pause its sim on a local dismissal) — it is a skippable overlay shown at Play-start.
- **Design-system components + reuse, no new scenes.** Build both overlays in code as `CanvasLayer` overlays via `ChimeraComponents` factories (`Panel`/`FieldLabel`/`Progress`/`Button`), mirror `HeroPickerOverlay` for the briefing and `CustomUiBridge`/`HeroPickerOverlay` for the quest-log; reuse `ChimeraToastHost` for the new-objective toast (`ToastVariant.Default`); use `WidgetFormat` for any objective counter/timer strings. No new `.tscn` files. No InputMap file exists — add one physical-`Key` branch in `MainScene._UnhandledInput` **above** the `:610` Edit-mode guard for the in-match quest-log toggle, picking a key the `:649-684` comments confirm is unclaimed (verify against `SelectionSystem`/`EntityPlacer`).

**Block If:**
- Objective state genuinely cannot ride the existing `DslVarTable` fold (a semantic the closed `Int`/reserved-var representation cannot express), so a dedicated new SoA store is required — that would force a `SimChecksum` `AlgoVersion` bump (→22) and a full all-world-golden re-baseline that this story does NOT pre-authorize (and which project memory flags as an unattended-safety hazard). HALT rather than introduce a new folded store.
- The `CanonicalModelHash` bump target 14 (or any needed integer) has already been claimed by another in-flight story — rebase and take the next free integer; if unresolvable, HALT (colliding-bump hazard, per memory).
- An AC cannot be met without adding a flat-channel (`ActionTypes`/`FromFlat`) surface, a new wire/replay format, or new folded sim state beyond the reserved DSL vars — HALT rather than expand scope silently.
- The differential guard (no-objective-node scenario folds byte-identical to pre-story apart from the `CanonicalModelHash` version integer) fails after the bump — HALT: the fold arm or re-record is corrupt; a green suite alone is NOT sufficient evidence.

**Never:**
- No new folded sim state and no `SimChecksum` `AlgoVersion` bump — objective state MUST ride the existing `DslVarTable` v16 fold.
- No strings in the tick — no objective title/description/id string ever enters sim state, folds into any checksum, or is formatted inside a `Tick`.
- No presentation state folded into `SimChecksum`; the quest-log/briefing overlays never write sim state and never desync (checksum byte-identical open vs closed).
- No second scenario-file loader — objectives attach to the one `ScenarioData` JSON through the existing `ScenarioSerializer`/`ScenarioValidator`/`ScenarioApplier`/`ScenarioDirector.LoadScenario` seam. Do not implement the GDD's separate `objectives.json` file.
- No scripting escape hatch — the three actions are closed-registry node kinds; an unknown kind rejects at parse with a located error naming the kind.
- No new `.tscn` scenes and no InputMap file. No hidden engine-only objective opcode — the actions are public DSL leaves.
- Out of scope: trigger-debugging overlay (Story 7.15); N-faction alliance changes (7.12, already landed); any win-evaluation logic (owned by `WinConditionSystem`, 7.11) — this story only reads the preset to synthesize a default objective, it does not evaluate wins.

## Design Notes

**Why ride `DslVarTable`, not a dedicated store.** The epic and story explicitly designate objective state as "DSL-variable-class sim state (folds via the existing DSL store fold — no new bump if it rides that store)." A dedicated `ObjectiveStore` would follow the clean `WinStateStore`/`TriggerEnabledStore` precedent but forces `SimChecksum.AlgoVersion` →22 and a full all-world-golden re-baseline — the exact unattended-safety hazard project memory flags (prior passes HALTed on such re-baselines). Reserved DSL vars need only int state (the enum ordinal); titles/descriptions are static model strings rendered presentation-side. This keeps the `SimChecksum` surface untouched and the re-baseline down to the single `hero-start-state` golden forced by the unavoidable `CanonicalModelHash` node-kind fold.

**Reserved-var shape (golden example).** For effective objectives `[{id:"kill_boss"}, {id:"hold_hill"}]` the loader appends, after authored decls, two `Global Int` vars in a reserved namespace (e.g. an internal `objective:` prefix the validator bars authored names from), seeded from `initial_state`. `complete_objective("kill_boss")` runs `_vars.SetInt(slotFor["kill_boss"], (int)ObjectiveState.Complete)`. The value folds via the existing v16 `DslVarTable.FoldInto` — no new fold code.

**Read-rail, not delegate.** Objective state must repaint a panel from scratch on Edit↔Play/late-join, so it uses the version-stamped `DslVarReadback` mirror (like `CustomUiBridge`), never a fire-and-forget `OnDisplayMessage`-style delegate (which loses state).
