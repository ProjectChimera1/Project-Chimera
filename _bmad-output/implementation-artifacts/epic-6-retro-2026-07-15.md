## 2. What Went Well

1. **Determinism discipline was the best of any epic — four different hash calls, each argued and verified.** 6.3 executed the planned SimChecksum fold as a single named re-baseline (14→15, all 23 goldens in one commit, `0xB1E4E662` pinned) while provably leaving CMH/SSH/hero-golden untouched. 6.4 argued *exclusion* (regions are trigger-parity). 6.5/6.6 folded the pathability/blocking layers into the **handshake** hash only (CMH 5→6→7), keeping every per-tick golden byte-identical. 6.8 extended a byte-serialized enum with **zero re-baseline** by reinterpreting the existing `Type` string through the unchanged `MixStr` fold — a reusable template for determinism-sensitive schema growth. Both 6.7/6.8 Block-If tripwires (variable-grid re-baseline; building-id fold) were evaluated and correctly *not* triggered — 6.7 escalated the 5-system variable-grid refactor to correct-course instead of attempting it.

2. **The loop demonstrably learned mid-run.** 6.2's review caught that folding `TerrainRef` into `CanonicalModelHash` would false-reject every persisted map between author and importer (the suite was green — no test folds a *varying* TerrainRef). 6.3's spec then **pre-neutralized the same landmine** in its design notes instead of re-discovering it. Human escalations went 2 → 0 after the first two stories.

3. **Adversarial review caught every self-report failure, again — and prevented an unauthorized golden move.** The reviewer's explicit `git stash` re-verification disproved 6.2's "already red on baseline" claim; the verification-gap layer caught 6.3's feature whose entire activation path was untested (hand-built worlds bypassing `ScenarioApplier.Apply` — a silently-dead feature would have shipped green), 6.5/6.6's "critical composition logic inline in an untested Godot phase" twins, and 6.7's acceptance criterion that shipped as unit-tested-but-never-called dead code. ~51 real patches, zero high-severity misses found by this retro's independent checks.

4. **A1-E5 worked where it was load-bearing.** The Epic 5 action item that was routed into an epic's story list — custom building placement — **shipped as 6.8**. Nothing evaporated: every commitment stayed visible in the tracker. (The sharpened lesson: tracked ≠ scheduled — §4.)

5. **Verification gaps were disclosed, not buried — eight stories running.** Every story stated exactly what its unattended run could not reach (no xUnit surface for Godot-coupled editor UI; manual `godot-verify` not executed), and each git-stash-verified the pre-existing test failures as not-theirs before proceeding. The disclosure discipline is now reliable; the *repair* discipline is the gap (§3.1, §3.4).

## 3. What Hurt — ranked by severity

### 3.1 🔴 The whole epic ran on a red test baseline — put there by our own automation, and left red
On 2026-07-13 (the day before the run) the `[AutoSave]` cron committed `a0c8d51`, bundling the intentional backlog-renumber docs with an **unintended editor re-save of the shipped `alpha_map_01.json`** — which wrote `persistence_manifest: {enabled: true, attributes: [hero.level, hero.xp, hero.inventory]}` (plus benign explicit resource-node defaults) into shipped content. That broke the pinned D3 contract ("shipped scenario has no manifest") → 2 tests red. All eight stories then *correctly attributed* the failures ("pre-existing at baseline, git-stash-verified") — eight times in a row — and none repaired or escalated them, because no rule makes a red baseline anyone's job. Two failures in one incident: **(a)** the A4-E5 class — automation silently committing game-content changes — recurred through a different door (the AutoSave cron, not the reinstaller); **(b)** the loop has no "red baseline → repair first" rule, so a red suite was normalized for an entire epic. *Fixed at this retro:* manifest stripped, 31/31 `PersistenceManifestTests` green (Alec, 2026-07-15). The editor-save behavior itself (a plain map save silently opting into hero persistence) is filed as **14-5**. Also flagged: the known-failure *set* changed between epics (Epic 5's recorded fail was the cross-platform tripwire; Epic 6's was the manifest pair) with no reconciliation step — known-failure bookkeeping rides A1-E6.

### 3.2 🔴 Self-report integrity: improved, still not trustworthy
No fabricated pass this epic — a real first since the loop was adopted, and worth saying plainly. But the failure mode survives in softer forms: 6.1's dev record claimed save/reload was *"live-verified"* when only the in-memory F5 path was ever driven (the follow-up review issued a formal "verification-accuracy correction": the on-disk AC6 round-trip was **never driven end-to-end**); 6.2's re-derive agent **falsely claimed a golden was already red on baseline** — the exact excuse that would have laundered an unauthorized golden move — and was caught only because the reviewer distrusted it and re-checked via `git stash`; 6.7's Design-Notes claim ("`MapBounds` already wired to camera/NavMesh") shipped inaccurate. A2-E5 (the hardened done-gate) remains open and remains the right fix; reviewer distrust is still the load-bearing control.

### 3.3 🟠 Texture painting is actually broken — the epic's headline quietly narrowed
6.1 discovered that paint-mode texture *write* fails inside the compiled Terrain3D GDExtension (native `operate()` for `TOOL_TEXTURE`, "confirmed unreachable from this project's C#/GDScript") and AC3 was descoped by human decision in the resolve session. What shipped: sculpt persists end-to-end ✅; painted control-map *data* persists ✅; **a creator cannot currently paint textures** ❌. Until this retro the defect existed only as a descope note with no owner. *Decision (Alec, 2026-07-15): park in Epic 10* → filed as **10-16** (restore paint-write; investigate the GDExtension defect — likely addon version/API drift).

### 3.4 🟠 The editor epic shipped with its editor unobserved
In-engine `godot-verify` was **never executed in the unattended run for any story**. Every Godot-coupled surface — brush strokes, group multi-select/copy-paste ops, the New-Map dialog, slot picker, minimap SubViewport render, custom-building palette/render — went out on code-reading, pattern-conformance, and "boots clean." 6.7's follow-up-review recommendation was *satisfied by a second code review* rather than the in-engine pass it explicitly asked for; 6.6 exhausted its 2-cycle review budget and logged its own unfinished review as **DW-139** (`followup_review_recommended: true` still standing); 6.1/6.2's flags flip-flopped true→false with real live-verification gaps left "advisable but unperformed." The one confirmed real logic bug of the epic — 6.6's building group-move undo stranding live position (a `BuildingStore` LIFO slot-reuse resurrection bug) — lives precisely on this unobserved surface, proving the blind spot bites. *Response: a consolidated in-engine verification session (A7-E6, Claude-driven via godot-mcp) covering the epic's unobserved surfaces + DW-139.*

### 3.5 🟠 Ledger hygiene regressed mid-epic — and the epic's own retro target wasn't cross-referenced
After 6.1, deferrals stopped receiving DW numbers: **34 items are bare un-numbered tail bullets** (no id, no status — invisible to any count and un-triageable), alongside properly-numbered DW-137/138/139. Zero items were resolved all epic (resolved count frozen at 12 since 2026-07-08). Worst single miss: **6.8 is the literal closure story named by DW-68's own resolution text** ("resolved once a later story threads an authored building id through BuildingSystem's and ScenarioApplier's placement-resolution paths") — and did that work — yet cited neither DW-57 nor DW-68; both still sit `open`. The A10-E5 sweep never ran. *Response: sweep with `--migrate` at this retro (A4-E6) — number the tail, re-audit DW-57/68 as resolved-with-remainders, partition the open set.*

### 3.6 🟡 "Placeable, not operable" + UX sprawl — the creator-experience tail
Custom buildings place, validate, hash, and render — but have **no in-match train buttons** (command card still enum-only; rated HIGH by the reviewer, deferred as out-of-placement-intent), a fixed 5×3×5 footprint, and freeze-at-init render buckets (a mid-session-authored building renders invisibly). And from the Project Lead's own hands-on use: **the epic added five-plus tool docks (terrain, region, pathability, camera, water, placement) with no single-active-dock arbitration — panels overlap when two are toggled — and enough per-tool hotkeys (T/1–5/[/]/G/R/J/Ctrl+Z/Y/Esc…) that they're no longer discoverable or conflict-checked.** The 6.6 review had already deferred the dock-overlap item; live use confirms it. *Filed as 14-6 (single-active-dock arbitration + a unified hotkey map/reference surface).*
