> **Split lineage:** This is the **2.5b** half of the comprehensive parent Story 2.5 (Ability Editor), split per Decision #7. **Story 2.5a** shipped the shippable core — the `AbilityEditorPanel` shell, the Simple-preset mode, the **completed `EffectNodeJsonConverter.Write`**, `AbilityPresets`, the `AbilityPresetMatcher` (added in 2.5a's code-review), the raw-JSON escape hatch, the validate-gated save, and the full Creation-Suite wiring. **2.5b is the advanced GUI:** the structured multi-effect graph composer that replaces the raw-JSON-only body of 2.5a's Advanced tab with a visual effect-tree builder (the raw-JSON pane stays, alongside, as the escape hatch). It depends on 2.5a being done and **reuses** all of 2.5a's machinery — the panel, the converter `Write`, the presets, the matcher, the validate-gated save path, the per-row UI builders, and the wiring. **It does not rebuild any of them.**

## Story

As a **creator**,
I want **the Ability Editor's advanced mode to compose a multi-effect ability as a structured effect tree — picking each node's kind from a dropdown and filling its fields, with add/remove/reorder/nest controls and no JSON typing — kept in sync with the raw-JSON pane and the common header**,
so that **I can build deep, multi-primitive abilities (e.g. a self-cost + an area-of-effect heal, wrapped in a sequence) visually, have them validated before they can break a match, and cast them — without writing code or hand-editing JSON**.

This finishes the **production path** for the D1 effect engine. Stories 2.1 (effect vocabulary), 2.2 (modifiers), 2.3 (the `AbilityDefinition` model + `Validated<T>` gate + JSON converter), and 2.4a/b (runtime cast spine + command-card UI) built the *consumption* path; Story 2.5a built the simple/raw-JSON *authoring* core. 2.5b layers the **structured visual composer** on top. It emits the **same `AbilityDefinition` JSON** that 2.3 loads and 2.4 attaches — **no new runtime path, no new sim state, no new file format.**

### 🚨 The #1 round-trip trap — `ShowJson` serializes the Simple model
`ShowJson()` (`AbilityEditorPanel.cs:401`) is hardcoded to `JsonSerializer.Serialize(BuildSimpleModel(), IndentedOptions)` — it renders the **Simple preset form**, not an arbitrary composed graph. ### 🚨 `EffectNode` and `Modifier` are IMMUTABLE — the composer needs a mutable authoring model
Every `EffectNode` subtype and `Modifier` is `sealed` with all-`readonly`, constructor-only fields (verified: `DirectHpDeltaEffect.Delta` `:23`; `HealEffect.Amount` `:19`; `DamageEffect.Amount`/`.Type` `:26`; `ApplyModifierEffect.Modifier` `:20`; `SequenceEffect.Children` `readonly EffectNode[]` via `params` ctor `:15`; `SearchAreaEffect.Radius`/`Filter`/`Child` `:26`; `PersistentEffect.{InitialEffect?,PeriodEffect?,ExpireEffect?,PeriodTicks,PeriodCount}` 5-arg ctor `:33`; `Modifier` ctor `:75`). A tree editor therefore **cannot mutate a node's field or children in place** — every per-field edit and every add/remove/reorder/nest must **rebuild the affected node via its constructor** (`new SearchAreaEffect(radius, filter, child)`, `new SequenceEffect(children…)`, `new Modifier(…)`, …) and re-thread the parent chain up to the root.

**Therefore the composer maintains a MUTABLE authoring/scratch model** (lightweight editable node records — or it rebuilds the affected subtree on each edit) and **materializes immutable `EffectNode`/`Modifier` instances only at Show-JSON / validate / save time.** ⚠ `SequenceEffect.Children` is a `readonly EffectNode[]`: the array *reference* is readonly but element *slots are writable* — **never** `seq.Children[i] = …`; this is the exact 1.12/1.13 "zombie-state" defect class. A mutable editor scratch model does **NOT** violate `AbilityDefinition`'s Decision #1=A ("the runtime graph IS the deserialization target — no parallel DTO tree", `AbilityDefinition.cs:10-11`): that decision governs **only the load/deserialization target** (no DTO layer between JSON and runtime nodes), **not the authoring UI**, which a visual tree editor inherently needs.

### `Fixed` round-trip precision note (load-bearing for AC2 sync)
`FixedJsonConverter.Write` emits `value.ToFloat()`; canonical identity is `Fixed.Raw` (16.16). For **authored magnitudes** (small ints/decimals like `80`, `6`, `4`, `1`) the value→float→value path round-trips exactly. **Judge round-trip identity on the reparsed graph's `Fixed.Raw` + node structure, not text equality.** When the composer serializes `Fixed` fields it goes through the **registered `FixedJsonConverter`** (via the already-built converter `Write`) — never a hand-rolled `ToFloat` in any new Godot-free helper (that trips analyzer CHM0005). ⚠ For the composer's **`Fixed` SpinBox rows**, note 2.5a deferred item 3: the Simple `amount`/`cooldown`/`radius` rows use `Step=1`/`0.5`, **coarser than `Fixed`'s 1/65536**, so touching a field snaps a loaded fractional value to the step (by design — Simple is coarse; raw-JSON is the precision path). The composer's `AddSpinRow` fields inherit this; keep the raw-JSON pane as the precision escape hatch, or use a finer step where exactness matters, and don't let a no-op visit silently quantize an untouched value.
