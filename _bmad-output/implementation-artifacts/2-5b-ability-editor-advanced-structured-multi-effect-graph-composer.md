## Story

As a **creator**,
I want **the Ability Editor's advanced mode to compose a multi-effect ability as a structured effect tree — picking each node's kind from a dropdown and filling its fields, with add/remove/reorder/nest controls and no JSON typing — and to have that structured view stay in sync with a raw-JSON pane**,
so that **I can build deep, multi-primitive abilities (e.g. a self-cost + an area-of-effect heal, wrapped in a sequence) visually, have them validated before they can break a match, and cast them — without writing code or hand-editing JSON**.

This finishes the **production path** for the D1 effect engine. Stories 2.1 (effect vocabulary), 2.2 (modifiers), 2.3 (the `AbilityDefinition` model + `Validated<T>` gate + JSON converter), and 2.4a/b (runtime cast spine + command-card UI) built the *consumption* path; Story 2.5a built the simple/raw-JSON *authoring* core. 2.5b layers the **structured visual composer** on top. It emits the **same `AbilityDefinition` JSON** that 2.3 loads and 2.4 attaches — **no new runtime path, no new sim state, no new file format.**

### 🚨 `EffectNode` and `Modifier` are IMMUTABLE — the composer needs a mutable authoring model
`EffectNode` and `Modifier` are **immutable**: every field is `readonly`, set **constructor-only** (verified — `DirectHpDeltaEffect.Delta` `DirectHpDeltaEffect.cs:19-23`; `DamageEffect.Amount`/`Type` `DamageEffect.cs:19-30`; `SearchAreaEffect.Radius`/`Filter`/`Child` `SearchAreaEffect.cs:16-31`; `SequenceEffect.Children` is a `readonly EffectNode[]` built from a `params` ctor `SequenceEffect.cs:12-15`; `PersistentEffect` `PersistentEffect.cs:17-41`; `ApplyModifierEffect.Modifier` `ApplyModifierEffect.cs:17-20`; `HealEffect.Amount` via the converter; `Modifier` `Modifier.cs:44-89`). A tree editor therefore **cannot mutate a node's field or children in place** — every per-field edit and every add/remove/reorder/nest must **rebuild the affected node instance via its constructor** (`new SearchAreaEffect(radius, filter, child)`, `new SequenceEffect(children…)`, `new Modifier(…)`, …) and re-thread the parent chain up to the root.

**Therefore the composer maintains a MUTABLE authoring/scratch model** (lightweight editable node records — or it rebuilds the affected subtree on each edit) and **materializes immutable `EffectNode`/`Modifier` instances only at Show-JSON / validate / save time**.

⚠ A mutable editor scratch model does **NOT** violate `AbilityDefinition`'s "**Decision #1 = A: the runtime graph IS the deserialization target — no parallel DTO tree**" (`AbilityDefinition.cs:10-11`). That decision governs **only the load/deserialization target** — the converter deserializes JSON straight into runtime `EffectNode`s with no DTO layer — **not the authoring UI**. Do **not** over-extend Decision #1=A into "the composer may not keep an editable model"; that is the opposite of what a visual tree editor requires.

### The validator + the AC3 error surface (reused by the composer's save)
`new AbilityValidator().Validate(AbilityDefinition? def)` (`godot/src/Core/Definitions/AbilityValidator.cs:35`) → `AbilityValidationResult { bool Ok; string? Error; Validated<AbilityDefinition> Value }` (`AbilityValidationResult.cs:12`). **Pure — never throws, never logs; stops at the FIRST failure.** On `Ok` it mints `Validated<AbilityDefinition>` via `ScenarioValidator.Proof` (the editor **cannot** mint one itself — `ValidatedSoleMinterTest` allow-lists only `ScenarioValidator.cs` + `AbilityValidator.cs`; route through `Validate`). `Error` is a **single located string** `ability '<id>'.<path>: <reason>` where `<path>` is dotted/indexed (`effect.children[2].child`, `effect.modifier.period_effect`). **There is no structured field locator** — surface this string (Decision #6; do not modify the validator). Checks order: id/targeting → cost/cooldown ≥0 → `effect` not null → `EffectBounds.Validate` (depth≤8, seq children≤8) → `WalkGraph` (`MaxTotalEffectNodes=64`, `MaxSearchAreaDepth=2`, Persistent re-entrancy, 0-child Sequence). ### `Fixed` round-trip precision note (load-bearing for AC2 sync)
`FixedJsonConverter.Write` emits `value.ToFloat()`; canonical identity is `Fixed.Raw` (16.16). For **authored magnitudes** (small ints/decimals like `80`, `6`, `4`, `1`) the value→float→value path round-trips exactly. **Judge round-trip identity on the reparsed graph's `Fixed.Raw` + node structure, not on text equality** — this is the AC2 round-trip assertion and matches how the samples are written. When the composer serializes `Fixed` fields, it goes through the **registered `FixedJsonConverter`** (via `JsonSerializer.Serialize(writer, value, options)` inside the already-built converter `Write`) — never a hand-rolled `value.ToFloat()` in any new Godot-free helper (that trips analyzer CHM0005, ToFloat outside the converter).
