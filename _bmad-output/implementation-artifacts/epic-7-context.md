# Epic 7 Context: Rich Trigger DSL & Custom Runtime UI

<!-- Generated from planning artifacts. Regenerate with compile-epic-context if planning docs change. -->

## Goal

Epic 7 turns the trigger system into a full "build any game" scripting layer while keeping the deterministic, server-validatable guarantees the platform depends on. It rebuilds the as-built flat, polled ECA triggers onto a single graph-canonical IR that embeds the existing effect subgraphs (no second executor), then layers on the creator-facing power features: typed scoped variables, deterministic timers, a pure Fixed-point expression sublanguage, custom events with acyclic same-tick dispatch, bounded loops/arrays with a fuel seatbelt, and a mandatory pre-tick validation gate. On top of that logic core it delivers custom runtime UI (a read rail for live scoreboards/counters and a networked write rail for interactive buttons), a visual node-graph editor over the shared IR, real win-condition presets evaluated in the sim, N-faction victory resolution, a broadened trigger/event vocabulary, an objectives/quest surface, and trigger debugging tools. The whole epic exists so creators can author WC3-class custom games across four interoperating tiers (T1 preset, T2 ECA, T3 graph, T4 natural language) on one representation that a multiplayer host can prove safe before any tick runs.

## Requirements & Constraints

- Every DSL construct must be **statically checkable and server-validated before any multiplayer tick**. There is no scripting escape hatch — no Lua/JASS/RunScript/customParams. All nodes come from a closed registry/grammar; unknown kinds are rejected at parse with a located error naming the kind.
- **One IR, all four tiers.** T1 presets, T2 ECA sentences, T3 node graph, and T4 natural-language authoring all emit and validate against the same graph representation. AI/NL authoring must be no more dangerous than human authoring (safe-by-construction, same gate).
- **Determinism is the hard gate.** Two headless runs of the same seeded scenario+command stream must produce a byte-identical SimChecksum. Any new live sim state (variables, timers, win counters, fuel counter, alliance mask, per-faction verdicts) folds into SimChecksum in declaration/ascending-id order, and each fold that changes the hash triggers a named, recorded golden re-baseline.
- **No floats, no culture-sensitivity, no wall-clock in the tick path.** All fractional numerics are Fixed 16.16; conversions happen only at the deserialization boundary; InvariantCulture is pinned process-wide. String formatting (int→string, Fixed→mm:ss) happens presentation-side only — strings never enter the tick.
- **Bounded by construction, not by runtime fuel.** Loop nesting cap-products, event-cascade cost over the transitive DAG closure, array capacity, widget count/depth/list-rows, and selection sizes are all rejected AT LOAD, never silently truncated at runtime. Named caps must be corpus-validated as a gate before lock, not treated as free tuning dials. A per-tick fuel budget exists only as a seatbelt for definitions that escape the load gate; when exhausted it halts deterministically at a whole-trigger boundary, never mid-Sequence.
- **Canonical model hash for start-state agreement.** FNV-64 over Fixed.Raw with fixed field order, enums as stable names, and `_editor` annotations excluded. Cosmetic edits (re-save, key reorder, whitespace, layout moves) must not change the hash; sim-semantic edits must. Hash 0 means not-computed and blocks; add schema_version + checksum_algo_version with legacy amnesty (absent ⇒ v1). Worst-case hash on a max-caps scenario must complete within the lobby-handshake budget (low tens of ms).
- **Read rail vs write rail separation for custom UI.** The read rail publishes a copy of already-checksummed state and is explicitly NOT in SimChecksum (cannot desync). The write rail mutates sim only through the lockstep command bus with sim-side per-event raiser authorization (never client-side button-disable). Local-only presentation buttons use a closed whitelist proven disjoint from sim/DSL namespaces and provably outside SimChecksum.
- **Win evaluation belongs in the sim, not presentation.** The current per-frame win switch in MainScene must move into a sim-layer WinConditionSystem emitting verdicts; presentation only reads verdicts. The two existing built-ins must be verified to behave identically after the move before new presets are added.

## Technical Decisions

- **Trigger DSL is one typed event/dataflow graph (`src/Dsl/`) that contains effect subgraphs** — it extends the existing effect validator/executor rather than adding a second system. The graph IR uses an id-keyed node list plus two sparse typed edge-lists (exec and data) with persistent integer node ids. Data edges carry type via wire color. It serializes canonically (nodes sorted by id; edges by (src, srcPort, dst, dstPort)).
- **Closed-registry NodeBase JsonConverter, `[JsonPolymorphic]` forbidden.** Round-trips every node by id over a CLOSED type registry. The flat legacy `TriggerDefinition[]` migrates losslessly into this IR (the T2 sentence list is a linear projection of an exec-edge chain) through the same canonical serialization — never a parallel code path.
- **Deterministic ordering everywhere.** Trigger evaluation order is total: Priority desc, then ascending persistent node-id — replacing the unstable `Array.Sort`. Timer/variable stores become dense index-keyed arrays (SoA), replacing dictionary enumeration. DSL event application orders by ascending faction-slot raiser.
- **DslVarTable** is a top-level sim store (sibling of BuildingStore/ResourceStore) with a closed value-type set (Int/Fixed/Bool/EntityRef/FactionRef/Point/TimerRef/Array<scalar>) and scopes Global / Per-player(0..7) / Trigger-local. Loop counters and trigger-local values are lexically scoped and freed at trigger end. Timers are expressed in integer ticks (no float→int truncation).
- **Expression sublanguage is CEL-shaped, pure, typed, side-effect-free.** Two-phase: parse + type-check + cost-estimate at load; evaluate a pre-checked Fixed-only AST in the tick. Operators + - * / mod, comparisons, && || !, and bounded built-ins (count/distance/min/max/abs). Division by zero and type mismatches are rejected at load with located errors. Expressions live in the IR as typed data edges.
- **Custom events: closed registry (names + typed params + per-event allowed-raiser set) + RaiseEvent node.** The eval loop is a same-tick work-list drain with zero per-tick heap allocation (allocate-at-load). The event-dispatch graph is proven a DAG at load; cycles rejected with located errors. Same-tick feedback (A→B→A) uses RaiseEventNextTick bounded by MaxNextTickEventQueue and folded into SimChecksum. Named caps: MaxCascadeOps, MaxEventFanOut, MaxEventCascadeDepth. The built-in unit_dies/on-death event carries killer/last-hit attribution (typed EntityRef/FactionRef) — ship the GENERIC seam only; faction content (e.g. Court "Glut") consumes it.
- **Loops are the only sanctioned iteration form.** ForEach over a collection snapshotted at loop entry in ascending entity-id order, plus ForEachBatched for large sets (cross-tick drip rides the next-tick event queue). No While/recursion/goto exists in the grammar. The as-built `Math.Min(count,50)` clamp is removed; the spawn cap reconciles to one named constant (64).
- **SimRng is the only randomness in sim.** RandomChoice (weighted branches) draws via seeded SimRng with an ascending-ID pre-sort rule; the validator forbids it until SimRng wiring is proven. Never `System.Random`/Godot RNG in sim.
- **Validator gate at the ApplyScenario/LoadScenario boundary** covers file, AI-gen, fallback, and replay-loaded paths. `LoadScenario` does zero validation today; `Validate(model)` becomes a mandatory pre-tick gate returning located errors. All content load returns `Validated<T>` (no throw / null-swallow).
- **Custom UI read rail:** a `CustomUiBridge` (modeled on `FogOfWarBridge`) publishes a read-only, double-buffered, per-variable version/dirty-stamped `DslVarReadback` once per tick at the tick boundary; presentation widgets pull in `_Process` and re-format only on version change. Closed widget vocabulary: Panel/Label/Counter/ProgressBar/Timer/Leaderboard/FloatingText/ItemList (data-bound repeater). Widget tree persists in ScenarioData and is covered by scenarioHash; caps ≤256 widgets / ≤8 depth / ≤64 list-rows.
- **Custom UI write rail:** `Button.Pressed` calls `LockstepManager.EnqueueDslEvent(eventId, args)` capturing LocalFaction as raiser, riding `TickCommandPacket` (capped parallel event list, MaxDslEventsPerTick). Pinned tick-phase order: apply DSL events → sim systems tick → ScenarioDirector drains the bus. `ApplyDslEvents` enforces the per-event allowed-raiser set sim-side. Replay format bumps to VERSION 2 with a DSL-event record kind threaded through all four command-application sites (live, spectator, ReplayPlayer.ApplyOrders, recorder); v1 replays are hard-rejected. Local-only whitelist: ToggleWidgetVisible/OpenSubPanel/CloseSelf/SetLocalUiVar.
- **T3 editor is GraphEdit-based and additive** — it renders/edits the already-graph-canonical IR (no GraphEdit/Godot types in the IR) as a replaceable view. T2↔T3 round-trips preserve the IR by persistent-node-id equality with no content migration. Node positions and authoring affordances persist verbatim in the excluded `_editor` annotation channel (not in scenarioHash). GraphEdit is "Experimental"/residual risk — the editor-agnostic IR lets it be swapped without touching other tiers.
- **WinConditionSystem** ticks in the deterministic loop in ascending-id order, emitting None / FactionWon(slot) / FactionLost(slot). Win state (KotH hold-tick counters, Timed-Survival deadline ticks, alliance mask, per-faction verdicts) are parallel SoA/declaration-index stores, integer ticks only, folded into SimChecksum. Four T1 presets (King of the Hill, Timed Survival, Assassination, Landmark Destruction) are turnkey graph-IR templates expressed entirely through the public DSL (no hidden engine opcode), proven by round-tripping through the schema unchanged. Invalid/missing preset params reject at load with a single located error. KotH contested-zone rule: counter does not advance for either contesting faction and resets when a faction no longer solely holds the zone. N-faction resolution uses a sim-owned alliance mask (default teams-of-1 FFA), owned in Epic 7 so the sim never depends on Epic 9; the existing `ScenarioDirector` OnVictory action stays as the advanced/T3 escape hatch.
- **Vocabulary breadth:** read-accessor leaves (entity HP/position/owner, player unit count filterable by tag/category, player resource amount, region unit count) as bounded snapshot reads; action leaves (OrderUnits reusing OrderApplier semantics; presentation-only MoveCamera/CinematicMode; PlaySound/PlayVfx riding the CombatEventQueue presentation bus); EnableTrigger/DisableTrigger/RunTrigger with a run-depth cap folded into rulesetHash and self-run cycle linting; new event sources (UnitDamaged, UnitTrained, AbilityCast, HeroLevel, PlayerChat) delivered deterministically at tick boundaries in ascending-id order. PlayerChat is the one wire-touching decision — must ride a tick-stamped replicated path so all clients evaluate on the same tick. Every new node must appear in all four tiers (no tier drift). Objective state is DSL-variable-class sim state (folds via the existing DSL store).

## UX & Interaction Patterns

- **Layered complexity / progressive disclosure** is mandatory: the ECA Trigger Editor must surface a simple preset entry AND a raw-IR escape hatch; the win-condition picker expands from 2 enum values to all six options (2 built-in + 4 presets) with each preset's required parameter fields shown inline.
- **Direct-manipulation custom-UI authoring:** a widget-palette builder on a fixed 16:9 canvas with 9-point anchors, `{variable}` binding, and trigger-driven visibility. Every BindVar must resolve and type-match the closed variable registry at load. Widgets render inside the 16:9 safe area.
- **T3 node-graph authoring:** typed exec/data wires with wire-color = type, a variables side table, and load-time validator errors routed onto the offending node. The T2 sentence editor shows a non-destructive read-only "edit in graph view" fallback for graph-only constructs.
- **Objectives & briefing surface:** an in-match quest-log panel (toggle key + new-objective toast, design-system components) reflecting ShowObjective/CompleteObjective/FailObjective live; a skippable pre-match briefing (map name/description, objective list, faction blurb) reused by Epic 13 campaign missions. A win-condition preset with no authored objectives auto-emits a default objective so every match shows its goal.
- **Trigger debugging overlay** (presentation-only, zero sim writes, checksum byte-identical open vs closed): live DSL variable values, tick-stamped fired-trigger log (last N), per-trigger fire counters, enabled state, filter/search, and click-to-navigate from a fired-log entry to its trigger.
- AI-generation affordances (trigger draft/apply) use a "Transmuting…" spinner and voice/microcopy conventions; when AI is unavailable, panels stay fully usable manually.

## Cross-Story Dependencies

- **Linear IR/DSL spine:** 7.1 (determinism baseline + re-pin) → 7.2 (graph IR + closed-registry converter + flat migration) → 7.3 (variables/timers/ECA) → 7.4 (expression layer, needs typed variables) → 7.5 (custom events, RaiseEvent args use expressions) → 7.6 (loops/arrays/fuel, ForEachBatched rides the next-tick event queue) → 7.7 (validator gate must cover loop/fuel/array caps).
- **Custom UI:** 7.8 read rail depends on the validated DslVarTable (7.7 gate + 7.3 variables). 7.9 write rail depends on 7.8 (buttons live in the widget tree) and 7.5 (buttons raise registered custom events); it is the sim-mutating landing where the golden harness is re-baselined; its merged replay-v2/local-whitelist arm depends on 7.9.
- **T3 editor:** 7.10 depends on 7.7 (renders validator errors) and the graph IR from 7.2.
- **Win conditions:** 7.11 depends on 7.3 (uses variables/timers/regions). 7.12 (N-faction) depends on 7.11 and owns the alliance mask that Epic 9's lobby wiring (9.15) later populates.
- **Vocabulary & surfaces:** 7.13 depends on the core DSL stories (7.3–7.6) and Epic 6 (6.4); its action-leaves arm also depends on 6.11 (named cameras) and 2.7 (CombatEventQueue), and its event-breadth arm on 3.13 (HeroLevel/kill attribution — shared hook, build once) and 2.7 (AbilityCast). 7.14 (objectives/briefing) depends on 7.11 and 7.13. 7.15 (debugging) depends on 7.13 and 3.10 (F5 playtest loop).
- **Upstream:** the epic assumes the prior D1 effect-graph epic delivered SimRng, the golden harness, and the reusable effect executor/validator — Epic 7 extends them, it does not build a second executor.
