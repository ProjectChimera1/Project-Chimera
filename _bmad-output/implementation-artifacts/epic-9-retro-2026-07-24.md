## 2. What Went Well

1. **The determinism discipline held under the hardest pressure the project has applied.** Roughly fifteen consecutive stories carried an explicit "any pre-existing committed golden moves ⇒ STOP, do not re-baseline" Block-If, and **it never tripped once.** The tick merge path was rewritten, the faction model doubled, teams were seeded into a checksummed store, and every committed golden stayed byte-identical with `AlgoVersion` pinned at 21. This is not luck — it is the direct payoff of the architectural call in 9.3 to put all determinism-critical logic in Godot-free cores under `src/Multiplayer/Server/**` (auto-globbed into the Tier-1 assembly), so the FR-39 goldens exercise the **real** merge code rather than a duplicate.

2. **Adversarial review caught three genuine desync classes nothing else would have.**
   - **9.4 (HIGH):** the directive maturity gate keyed on `MergedTickBuilder.EmittedThrough` — the *submission* frontier, which **leads** the *exec* frontier by up to `MAX_DELAY`. So the gate cleared while a lagging client still held the prior delay change pending; the server issued the next directive, the client dropped it, and two clients ran on different `_currentDelay` → different `issueTick` → desync. Reachable on the shipped 2-player path any time RTT changed twice. Fixed by arming the gate at `applyAtTick + MAX_DELAY`.
   - **9.5 (HIGH):** `LockstepManager.GoOffline()` — the only writer of `IsOnline = false` — had **zero callers**, and the manager survives every F5 Edit↔Play cycle. So after any online match as Player 2+, a subsequent offline playtest resolved "the local player" to the stale online faction: selection selected nothing, the command card went inert, the minimap mis-coloured. This was a regression *introduced by 9.5 itself* and caught by the same story's review.
   - **9.3 (medium):** the N=2 FR-39 golden was apply-order-**insensitive** — each faction ordered only its own disjoint units, so the golden the AC named as the ordering gate could not fail on a sub-bundle order flip. Rebuilt around a non-commutative DSL event fold so P1-then-P2 ≠ P2-then-P1.

3. **The loop escalated twice instead of fabricating, and both escalations were correct.** 9.1's entire scope had already shipped in Epic 1; the loop refused to invent make-work or a gratuitous `AlgoVersion` bump and stopped for a governance decision. 9.12's four reviewers converged that the online rail was **dormant** (no production caller constructed `OnlineProfileSource`) *and* that the spec's own `Never` clause contradicted its AC3 — a real internal contradiction, escalated rather than papered over. The resolution (WC3/Battle.net model: the server owns the record so a hand-edited local save is simply ignored online; host-side StartGame identity enforcement named as a tracked follow-up) is a genuine decision with a stated threat model, not a fudge.

4. **Verification-gap hunting matured into killing *vacuous* tests, not just missing ones.** Repeatedly the review's finding was "this test passes for the wrong reason": 9.4's EWMA smoothing was indistinguishable from last-sample-wins because every fixture fed 40 identical values; 9.6's drop golden passed with a **no-op injector** stubbed in; 9.15's e2e proved victory via `RazeFaction` while the fanned-in merged orders were inert, so a no-op `MergedTickApplier` passed every assertion; 9.16's completeness guard proved a field was *classified* as folded, not that the hash actually *moved* when it changed. Each was closed with a mutation-style test that goes RED on the stub.

5. **Compounding architecture, four epics deep.** The tagged envelope frozen in 9.3 was consumed verbatim by 9.11's replay v4 body — no re-implementation, no second codec to drift. 9.6's `DropController` mirrored 9.4's `DelayController` directive/ACK machinery. 9.14's `MatchAgreementHash` team fold and 9.16's `ContentHash` both composed into the gate 9.4 built without touching it. 9.16 extracted the typed effect-tree walk so `CanonicalModelHash` and `ContentHash` fold effects byte-identically **by construction**.

6. **The `AlgoVersion`-first discipline made a whole class of cross-version desync impossible.** Because `MatchAgreementHash` mixes its own version first and bumped 1→2→3 across the epic, any pre-9.16 peer *always* mismatches at the gate rather than starting a match on divergent content. 9.16's review even patched the block message to name build/version skew as the first candidate cause.

## 3. What Hurt — ranked by severity

### 3.1 🔴 Nothing shipped this epic was ever observed running — and the fix we built for exactly this went unused

Epic 9 produced the largest Godot-coupled surface in the project's history: the N-slot lobby (colorblind dots + glyphs, ready pills, ping, pre-match chat, scenario hash header), the main-menu **Multiplayer** entry, the content browser's sort dropdown / tag chips / thumbnails / subscribe / rate / auth prompts, the replay browser and playback controls (pause, 1×–8×, seek, perspective toggle), the generalized 4-slot game-over screen, the online hero picker, and the publish consent flow. A grep across all 16 specs finds **30 references to `godot-verify` / in-engine / live-verify — every single one phrased as "documented for the live-verify pass."** Zero ran. Every story's residual-risk section carries the same sentence Epic 7 and Epic 8 carried.

**The sharp part is the follow-through failure, not the debt itself.** A1-E8 — the native-Windows bmad-loop migration — **landed and validated green** (`1e38cc2`, `053baf7`). Its entire justification was that a Windows-native loop could drive godot-mcp *as a per-story step* and attach a state digest as evidence, structurally eliminating this class. The migration succeeded. Epic 9 ran on it. **And not one story used the capability.** We correctly diagnosed the root cause, correctly fixed it, and the symptom continued unchanged — because nothing in the loop's dev checklist *required* the new capability to be used. A capability that is available but not mandatory is, in practice, a capability that does not exist.

*Response: A1-E9 (make it a gate) + A2-E9 (catch-up session) — per Alec's decision this retro: fix the mechanism first, then clear the backlog.*

### 3.2 🟠 "Four-player verified end-to-end" is honest in the spec and narrower than it sounds

Story 9.15's own review forced its docstrings to state precisely what the proof covers, and this is worth quoting into the retro so nobody later reads the story title as more than it is:

- The positive run proves **liveness + unanimous accept** — one in-process canonical sim, its per-tick checksum echoed to four slots of a live `ServerHost(4)`. The quorum is green partly by construction.
- **Detection** is proven separately, by a synthetic minority-desync negative test.
- **Determinism** is same-process, run-vs-run byte-identity — **not** a cross-machine or cross-platform golden.

What was explicitly *not* exercised, in 9.15 and across the epic: live Nakama matchmaking and the parties API; a real 4-client LAN `join → chat → ready → start`; any mod.io call at all (publish, browse, download, subscribe, rate — 9.8/9.9/9.10 are entirely unexercised against the real service); whether a downloaded `.glb` actually renders in an exported build (9.9's defining behavior); and 9.12's online hero picker end-to-end, whose *reachability* is itself a flagged deferral ("soft-lock risk if the pre-match lobby has no placeable-hero scenario"). The **FR-39 two-machine LAN gate — the #1 pre-ship gate, carried since Epic 1 — remains un-run.**

Additional live-verification caveat worth recording: `LoopbackDesyncSelfTest` sends a hardcoded `GOOD` checksum rather than each peer's *computed* sim checksum, so no automated artifact anywhere runs N independent sims that compute and compare their own checksums. Literal 4-client zero-desync is proven only by the manual two-machine runbook.

*Decision (Alec, this retro): **defer all live verification to Epic 10.** Recorded as an accepted risk in §5 with its concrete consequence.*

### 3.3 🟠 A3-E8 recurred for a fourth consecutive epic — proven live, plus a baseline-hygiene relapse

All **15** Epic-9 `final_revision` hashes fail `git merge-base --is-ancestor <hash> HEAD`. Not one resolves from HEAD; `git checkout <final_revision>` is impossible for every story in the epic. This is A1-E7(b) → A3-E8 recurring for the fourth straight epic (A6-E6 → A1-E7 → A3-E8 → open).

As in Epic 8 the recurrence is **benign** — the squash chain itself is clean and one-squash-per-story held (9.14's baseline `2f72b72` == 9.12's squash; 9.15's baseline `9952521` == 9.14's squash; 9.16's baseline `9377f3d` == 9.15's squash). But two stories relapsed on baseline hygiene: **9.3 and 9.7 took their `baseline_revision` from mid-run `[AutoSave]` commits** (`2cfb324`, `7fbcca1`) — precisely what A6-E6(a) named.

**Content-commit guard held, and I verified it rather than assuming:** all nine in-range `[AutoSave]` commits touched **zero** files under `godot/resources/data/**`. The Epic-5 5.3 class did not recur.

*Response: A4-E9 (carries A3-E8, now with the AutoSave-baseline half re-attached).*

### 3.4 🟡 The ledger got materially worse — the sweep debt roughly tripled while waiting

Epic 9 filed **67 new deferred-work items, every one an un-numbered flat bullet.** The ledger now holds **201 numbered `DW-` entries (154 open) plus 125 un-numbered flat bullets** — up from the 43 flagged at the Epic 8 retro. A2-E8's `--migrate` sweep has now been owed across **three consecutive retros** (A4-E7 → A2-E8 → open), and the un-numbered backlog nearly tripled in the interval.

Some of the 67 are genuinely material and worth naming so they don't drown in volume:
- **9.11:** the `rulesetHash` is embedded in the replay v4 header but **never re-gated on playback** — only the scenario hash is. A ruleset-only drift can still silently desync a replayed match.
- **9.3:** a client-triggered drop of an intermediate tick's bundle (faction spoof / over-count / malformed) makes that tick's fan-in never complete → a permanent, non-contiguous, **no-HALT** match freeze. A distinct trigger from the disconnect freeze 9.6 closed.
- **9.6:** the post-drop floor-1 quorum reports **PASS** on the human-facing MATCH SUMMARY when it is liveness-only, not cross-peer attestation. The doc comments were corrected; the observable verdict surface still over-claims.
- **9.16:** the shared effect-walk's `default` case folds only the **type name** — an `EffectNode`/`Modifier` subtype's field values are invisible to the content hash. Pre-existing, but 9.16 widened its blast radius from DSL embeds to all ability/item effects.
- **9.9:** load-path ingest enumerates the extracted assets **directory** rather than the verified manifest `AssetFiles`, and the directory is never cleared — a stale `.glb` from a prior same-`Id` import can render unverified.

*Response: A3-E9 — run the sweep before Epic 11 opens (Alec's decision this retro).*

### 3.5 🟡 A6-E7's production-wiring smoke is still reactive, not standing

Epic 9 finally had real surface for A6-E7 (Epic 8 had none), and the item worked — but only *after* review found it, three passes deep. Story 9.14 needed live-host wiring guards for **four** mask consumers (`CombatSystem`, `FogOfWarSystem`, `ProjectileSystem`, `AbilityCastSystem`), and all four were added by the review loop across passes 1→2→3, not by dev up front. The failure mode each guards is exactly the documented class: drop the `Alliances` constructor arg from `SimulationHost` and live allied splash / ability targeting silently breaks **with every test still green**, because all goldens are FFA no-ops. The item remains open as a standing dev-checklist commitment; Epic 11's 11.3 (checksum-verified full-world save/load) will exercise it again.

### 3.6 🟡 Two new bmad-loop engine bugs, both costing manual intervention

- **Review-phase resultless nudge-loop:** a run stuck in "review-running" ~1h after commit, because `bmad-dev-auto` has no review-completion contract. Diagnosed via `resultless-stops.jsonl`; safe to `bmad-loop stop`.
- **`bmad-loop resume` skips re-arm:** after resolving 9.12's escalation, `resume` committed the resolution but **jumped to the next story**, leaving 9.12 stuck blocked forever. Recovery needed a hand-authored commit (`dd896a6`, "flip resolved spec status blocked→draft") to get it re-driven. First hit on 9.12.

Both are engine bugs for the maintainer, not code failures.

### 3.7 🟡 Sequencing drifted silently from a recorded decision

The 2026-07-01 sprint-change proposal explicitly sequenced **Epic 11 BEFORE Epic 9** — the rationale, still written in `epics.md:3485` and in the `sprint-status.yaml` comment above the epic-11 block, is that *"multiplayer verification needs this shell to exist."* Epic 8's retro §6 named Epic 11 as next. Epic 9 ran instead, and no artifact records the reversal or its reasoning. The consequence is visible in the epic: 9.14 could only *display* teams because there is no setup screen to assign them; 9.7's lobby had to invent its own entry point; 9.15's 4-player e2e is headless partly because there is no shell to drive four players through. None of this broke anything — but a recorded sequencing decision was silently inverted, which is the kind of drift that is only ever noticed at a retro.
