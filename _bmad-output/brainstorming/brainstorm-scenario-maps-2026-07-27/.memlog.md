- (direction) Core tension Alec set: maps must be EFFICIENT but VERY customizable — creators must not feel size-constrained, but not infinite/never-loads either
- (insight by coach) KEY REFRAME: the cost fork is not map SIZE, it's SEAMLESSNESS. Many fixed-256 maps linked by transitions = grids never re-dimension = NOT a determinism story. Seamless walk-across-the-seam = the expensive version that moves every golden.
- (idea by coach) The loading corridor: a tiny connector map whose only job is to be walked through (canyon, sewer, rope bridge) — streaming budget dressed as level design, as vanilla WoW did. Goal was never 'seamless', it was 'unnoticed'.
- (insight by coach) Morphological dials surfaced: (1) how maps connect (2) what's live at once (3) who authors the link (4) footprint per map (5) population budget across maps (6) persistence/reset
- (idea by user) Transition = explicit loading screen, creator-authored: click-through slideshow with a loading bar, or a single creator-made image per dungeon
- (idea by user) During the load the player can browse inventory, equipment, and skill tree — and ideally rearrange things while loading
- (direction) Alec: the loading screen must be a creator-buildable feature, opt-in, used when they want to expand their playing field
- (idea by coach) Gear moves during a load are QUEUED, not applied — held and replayed in order on the first tick of the new map; feels instant, keeps lockstep intact. Solo can apply live.
- (insight by coach) The loading screen is also the natural home for the lockstep sync barrier — all peers must arrive on the same tick anyway. Atmosphere and architecture want the same thing.
- (idea by coach) Connector vocabulary (20): cave mouth, stone circle, one-way hole, key-locked door, boat ride, gryphon flight path, elevator/mine cart, sewer grate, whirlpool, being swallowed, wardrobe/mirror, death-respawn, summoning ritual pulling other players, collapsing bridge, fog wall, merchant caravan passage, tavern door, sleep-until-nightfall, boss knocks you through the floor, unlock-by-walking teleport pad
- (idea by coach) Discovery-gated fast travel: a portal only works once you've walked there the slow way (requires_discovered flag). Makes the world feel big, then rewards exploration.
- (decision by user) On a player leaving: the other four keep playing — the game does not stop
- (idea by user) Ideal: a smart AI takes over the absent hero, authored BY THE CREATOR per hero type ('spec'); the hero keeps performing its duty but earns no progress for the absent player
- (idea by user) Simpler and Alec prefers it: the absent hero is ASSIGNED to the remaining players — they control it, or agree among themselves who takes it
- (idea by user) Players VOTE on whether the disconnected player's hero stays in play or is removed
- (insight by coach) Creator-authored AI is a PRIORITY LIST (condition -> action, ordered), not human-like AI — 4-5 rules per role plays a competent dungeon. Same shape as Chimera's trigger system, so it's a preset library on planned work, not a new engine. Genuine catch = AI must be deterministic (float->Fixed) before running in lockstep.
- (idea by coach) Ship adopt-the-hero FIRST, bot later as a preference: an RTS engine controls multiple units natively, and 'who takes Dave's healer?' turns a lost player into party drama instead of admin
- (idea by coach) Creator toggle for disconnect handling: vote / auto-adopt / auto-bot / hero vanishes
- (idea by coach) Maybe town isn't a PLACE: pack mule that follows the party, mailbox, summonable merchant on cooldown, 'sell junk' button. If the shop is UI, nobody splits the party and the multi-live-map cost disappears.
- (decision by user) PLATFORM RULE: pack mule / scattered stores / a town to portal back to are all CREATOR choices authored in the map creator with triggers — not decisions Alec makes for them
- (technique) started How Might We
- (idea by user) Growth mechanism = instances with loading screens leading to more map
- (idea by user) 'Add additional map' icon shows a PLACEMENT GRID — you pick where the new map sits relative to the current one, like a + on a grid
- (idea by user) Keep the existing map size as the good unit; adding another map just gives the creator teleport-the-hero via any icon, cave entrance, building, etc.
- (idea by user) FIRST-TIME GUIDED SETUP in the map editor for multi-map: (1) select map addition (2) pick the tile-grid slot (3) 'map switcher' to choose which map you're editing when a creation has >1 (4) pick a location, right-click, dropdown 'add link to another map' (5) place the link -> editor ZOOMS to the other map and asks for the linking location (6) this auto-generates the transfer triggers, and the return trip if the creator wants it
- (decision by user) Map count: as many as we can, but cap at a safe number if necessary
- (idea by user) Deleting a map must handle referential integrity: re-route the linked locations, or ask the creator whether to delete the linked triggers
- (idea by user) World feels enormous via instances of more map area
- (idea by user) An AI knowledge-base inside the editor that understands the CURRENT map configuration and the creation process, answering the creator's questions live while they work
- (insight by coach) ALEC'S CORE TENSION RESOLVES: authored maps = unlimited (they're just files on disk); LIVE maps = capped (each needs its own flow field, pathability mask, fog grid, and tick budget). 'Efficient AND unconstrained' is achievable because the two words apply to different things.
- (insight by coach) The placement grid gives relative map coordinates for free -> a world atlas/minimap, and forward-compatibility if seamless adjacency is ever wanted later. Cheap now, valuable later.
- (insight by coach) Two-ended link authoring (place one end, editor zooms to the far map for the other end) makes a half-wired link structurally impossible — the class of bug that plagues RPG-Maker-style transfer events
- (idea by coach) Link authoring refinements: 'also create the return trip' checkbox (most links are two-way); links are named stable IDs so the creator reads 'Cave Mouth -> Deep Cavern (entrance)'; draw link lines on the world atlas; deleting a map reports 'N links point here' before it lets you
