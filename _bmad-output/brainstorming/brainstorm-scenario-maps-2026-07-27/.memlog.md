- (insight by coach) REFRAME OF THE WHOLE SESSION: the requirement was never map SIZE, it was UNBOUNDED PROGRESSION. Three independent mechanisms serve it at three prices: (1) bigger map = expensive AND now unnecessary; (2) multi-map in one document = the Epic 11 project; (3) portable hero saves between separate creations = CHEAPEST and the only one that scales without limit.
- (insight by coach) Hero save/load is the WC3-campaign model: a serialized hero record (level, skill tree, inventory, gold) written at Victory, read at load. It needs NO grid work, NO live-map cap, NO lockstep transition — the handoff happens BETWEEN matches. A creator could ship a 20-map series on this alone, before multi-map runtime exists.
- (insight by coach) UNIFICATION: the loading screen and the hero save are the same concept at two scales. Creator flow can present one question — 'where does this exit lead?' -> another map in this project (loading screen) OR another project entirely (hero save). Same authoring gesture, wildly different cost.
- (insight by coach) Hero-save open questions for the spec: tamper (a save file is editable — sign it, or make it a creator toggle); content drift (an old save referencing an ability map2 no longer has must fail gracefully through the existing content-validation gate); co-op (every player's hero save becomes part of the match start state, so it must fold into the FNV-64 canonical start-state hash the architecture already defines)
- (insight by coach) Hero saves make the live-map cap permanently a non-issue: even if the runtime never holds more than one live map, a creator ships 100 maps as a campaign. Also closes the loop on Alec's opening pillar — scarce mana/gold only MATTER across a series if consumables and gold ride the save.
- (insight by coach) A hero is a portable record either way: the same serialization that lets a remaining player ADOPT an abandoned hero mid-match is what writes a hero to disk between matches. Build the hero record once, it serves both.
- (decision by coach) RECOMMENDATION on sequencing: hero save/load should be the FIRST story of the Epic 11 tail block, not the last — it is the cheapest mechanism, it delivers the long-term-progression vision on its own, and it de-risks multi-map runtime by proving hero serialization first.
